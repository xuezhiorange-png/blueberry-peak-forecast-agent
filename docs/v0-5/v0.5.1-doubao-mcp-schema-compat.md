# v0.5.1 Doubao MCP schema compatibility

This patch is limited to the input-schema projection exposed by MCP discovery.
It does not change the AREA_YIELD_B1_V1 forecast, runtime validation, REST
contracts, persistence, authority, or tool names.

```ini
FORECAST_MATH_CHANGED=false
MODEL_CHANGED=false
AUTHORITY_CHANGED=false
DB_SCHEMA_CHANGED=false
MCP_TOOL_CONTRACT_SEMANTICS_CHANGED=false
MCP_DISCOVERY_SCHEMA_PROJECTION_CHANGED=true
```

For integer input constraints that are explicitly expressed as
`exclusiveMinimum: 0`, the MCP discovery projection emits the equivalent
`minimum: 1` form. The projection is recursive, deep-copy based, and applies
only to input schemas. If a conflicting `minimum` is already present, it fails
closed rather than overwriting it.

The server-side Pydantic models remain authoritative. Values such as `run_id=0`
and `rerun_of_run_id=0` continue to be rejected at runtime. Output schemas and
the nine tool names are unchanged. The v0.5.0 tag is not modified; this is a
Draft v0.5.1 compatibility patch for review.
