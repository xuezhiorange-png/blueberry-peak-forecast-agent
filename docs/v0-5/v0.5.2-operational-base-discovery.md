# v0.5.2 operational base discovery

本补丁只增加一个面向 MCP 的只读基地发现工具，解决外部工作助手需要先知道
`base_id` 才能调用 operational peak 工具的问题。预测数学、authority、持久化表、模型和
既有九个工具合同均不改变。

## Frozen contract

- Tool: `search_blueberry_operational_bases`
- MCP surface: 10 tools total
- Input: optional `query` (string, maximum 200 characters) and `limit` (1--100, default 20)
- Empty or whitespace-only query returns active registered bases, subject to `limit`.
- Search fields are only `base_id` and `canonical_base_name`.
- Normalization is Unicode NFKC, trim, and casefold. There is no suffix removal, fuzzy match,
  pinyin conversion, edit distance, geographic inference, or LLM selection.
- Match priority is exact base ID, exact canonical name, canonical-name substring, then base-ID
  substring. Ambiguous substring matches are returned as multiple candidates.
- Inactive bases are excluded. The tool never selects a base and never calls the forecast service.

Each result returns only `base_id`, `canonical_base_name`, `productive_area_mu`, `area_basis`,
`active`, `match_type`, the total `match_count`, the requested `query`, and the validated
`authority_hash`. It does not expose authority paths, raw registry/profile payloads, or private
files.

When a user asks to create an operational peak run, an exact registered base ID or exact
canonical base name may be passed directly. A partial or unknown name must first be resolved by
the caller through the search tool; create remains fail-closed and does not add fuzzy matching or
Global fallback.

## Product boundary

The search adapter calls the existing `load_operational_peak_authority()` and reads its validated
`snapshot.registry["bases"]`. It is mounted on the same stdio and Streamable HTTP MCP server as
the existing tools. `AREA_YIELD_B1_V1`, `OPERATIONAL_PEAK_POLICY_V1`, and all forecast/persistence
calculations remain unchanged.

External-work-assistant integration remains a separate deployment concern. This patch provides a
stable discovery surface; it does not register or deploy a Doubao runtime.
