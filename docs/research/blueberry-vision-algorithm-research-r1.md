## 2. 四路线总览

| 路线 | 直接可验证的产物 | 相对工作与主要不确定性 | 首个实验候选 |
| --- | --- | --- | --- |
| A 目标检测 | 同一单图范围的可见果框、类别、置信度与可见计数 | box 标签相对便于启动；小果、遮挡、密集果串和重复检测可能主导误差 | **有条件首选**：Owner 确认可见果任务、许可和标签后评估有限 YOLO 类候选，不冻结最终架构 |
| B 实例分割 | 逐可见实例 mask、实例数及边界质量 | 更细边界可能减少粘连，需额外 mask 工时/资源；完全隐藏果仍不可识别 | A 的拥挤误差需要进一步解释时，在匹配图像/独立测试范围开展增量比较 |

## 3. 路线 A：目标检测与可见计数

**原理。** YOLO 类单阶段检测器从图像特征回归每个目标的 bounding box、类别和置信度（S1/S3）；
多尺度特征可处理不同大小目标，但最终效果取决于拍摄尺度与标签。
推理后的重复抑制、置信阈值、切片图像边缘合并和计数规则必须视为实验配置。
人工复核计数及简易颜色/连通区域方法可作诊断基线，不能预设深度模型必然胜出。

**数据及标签。** 需要已授权原图、逐可见果 object ID/box、逐图人工复核可见数、
品种/基地/日期/会话/样方/设备、遮挡与小目标属性。Owner 须先定义可标注最小尺度、
部分遮挡阈值、出界果、crowd/ignore、枯果/花叶/非目标、不可判读及真实空图。
果串不自动作为单果；缺标注不是无果。标注须记录版本、复核、来源和 available_at。

**指标。** 检测报告 Precision、Recall、bbox mAP@0.50 与 mAP@0.50:0.95；
计数报告每图 MAE、Bias（正值为过计）、密度/遮挡/小目标分层、空图误检及拒判/推理失败率。
需同时记录可计算分母与独立组数，不能只报成功图片。标准 COCO maxDets=100（S4）的影响
需公开：记录 >100 GT 的图片和截断率；若采用更大上限，预注册为单独指标。
操作点阈值和 NMS 只在 validation 选择，不在 test 调优。

**难点。** 密集果串的相邻框可能在 NMS 中被误删，低阈值又可能重复计数；完全遮挡果
不能从单图直接观察。小果下采样后可能失去可辨信息，扩大输入/切片增加算力并引入
边缘重复；反光、阴影、蜡粉、叶片背景及设备曝光带来域差异（S5）。视频连续帧中
重复看到同一果实，不能把每帧数量相加当植株总数；tracking/re-identification 需要另建
身份、遮挡恢复和独立核对实验，不在本轮实现。

**成本与资源规划。** 每个可见果需框和复核；高密度图耗时随实例数增长，错误/歧义需回访。
启动时先测授权小样本标注工时与一致性，再定总量，不能套用 S5 的其他果类工时。
未来有限小模型实验可将单张 12–24 GB 显存 GPU、32 GB 级 RAM 作为预算询价档位；
图像大小、batch、增强与框架会改变峰值，需 smoke run 后确定，不是最低硬件保证。
离线 CPU 推理可作对照，边缘端 GPU/NPU 是否必要取决于目标设备/延迟。
测 p50/p95 端到端延迟、内存、失败率，不能引用 S1/S3 的 FPS 承诺设备实时性。

**系统关联与首轮判断。** 仅产生独立 VisionObservation 中的可见计数/预测来源。
保持 canonical Base 或 unresolved、season、样方、时间、label/model/source hash。
不写正式 Forecast Intelligence run、不改变 Harvest State，不换算 kg。
在许可、可见定义、独立测试和资源单独批准后，A 是最小可解释的首轮候选。

## 4. 路线 B：实例分割

**原理。** Mask R-CNN 类方法在检测基础上预测每实例 mask（S2）；也可比较一阶段实例
分割候选，不预先指定实现。实例分割区分不同果实；语义“果实区域”分割只给前景像素，
连在一起的果串并不会自动变成可靠实例数。实例边界信息可能帮助分开粘连目标，
这是蓝莓上的待验证假设，而非已证明收益。

**数据及标签。** 同一批准图片的逐可见果 mask、object ID、类别、box/计数及遮挡属性。
需冻结 visible-only 或 amodal 口径；首个候选宜可见边界，不凭想象画隐藏果轮廓。
明确相互遮挡、阴影边界、果柄、部分出界、严重 crowd/ignore 及无法分实例的处理。
标注版本不能从 box 版本推断；自动生成 mask 要保留工具来源并人工独立复核。

**指标。** mask mAP@0.50 / @0.50:0.95、逐实例可见计数 MAE/Bias、密度/遮挡分层、
不可界定比例和 QA disagreement。与 A 使用同一独立 holdout、相同可见定义与范围，
报告成对计数误差差异及额外工时/资源；不能比较不同难度样本得出“分割更好”。
高 mask IoU 不等于正确计数，mask mAP 与计数指标必须分别报告。

**难点。** 接触边界、遮挡后零碎可见部分和相近颜色使实例划分不确定；分错实例仍会
过计/漏计。mask 只能表示可见/经定义推断区域，不能揭示完全隐藏果。
图像边缘、低分辨率、标注者之间边界差异会放大评估不稳定性。
部署增加 mask 输出、编码/合并、显存和后处理复杂度；一阶段分割未必比所有检测器慢，
应在相同硬件、分辨率和后处理条件实测，不能照搬 S2 的历史 FPS。

**成本与资源规划。** 逐实例 polygon/mask、边界复核和对象对应通常比画框更重；
S5 支持标注成本有差异，但其比例不能用于蓝莓预算。先在 A 的批准困难子样本测
box/mask 同图工时；用实测每实例时间、返工率与复核比例估总工时。
未来高分辨率多实例方案可询价单张 24–48 GB GPU、32–64 GB RAM，或降低 batch/采用
小模型；仅为预算档位，真实需求必须经单独授权测定。推理需同时衡量 mask 编码/传输
与吞吐，不仅网络 forward；存储另计标注和每实例 mask 字节。

**系统关联与首轮判断。** 独立保存实例来源与 annotation/model version，
可作为 A 的计数误差诊断或成熟标签实例定位，不覆盖原观测、不汇总为重量。
B 不默认作为首个实验；仅当 A 的密集/遮挡误差和额外标注收益值得验证时，
使用匹配测试集开展增量研究。

## 5. 路线 C：成熟分类或分割

**原理。** 候选一是从已定位果实 crop/mask 提取经批准的颜色、纹理/形状特征，
以 HSV/Lab 统计和简单分类器建立可解释基线；候选二是轻量 CNN 对逐果 crop 分类；
候选三是成熟类别语义/实例分割。颜色空间转换不自动消除光照/白平衡影响。
只有生物/业务参照支持，才能把视觉特征关联到成熟阶段；RGB 无法直接测糖度、
硬度、口感或商品果率。S6 同时使用颜色、触感和试尝，且不同品种颜色不统一。

**数据及标签。** Owner 批准的成熟等级定义/version、逐果 GT 类别或像素类别、
UNKNOWN、标注证据、品种/拍摄环境、同一果实 crop 与原图/对象对应。
若业务目标是“可采”而非“颜色外观”，需要独立采收判断或批准的糖度/硬度等参照
及测量方法/时间，不以历史入厂 grade 替代果园成熟标签。
颜色卡、固定曝光/距离和设备原始设置是候选采集措施，须先评估成本与场景适用性。

**指标。** 混淆矩阵、每类 Recall/支持数、macro recall 的可计算类范围、
UNKNOWN/ABSTAIN 比例，按品种/光照/设备/日期分层；必要时另冻结概率校准指标。
在人工 GT crop 上的分类与检测→分级端到端评估分开报告，后者漏检也算失败。
像素分割另报经批准的 IoU/Dice/ignore 规则，不把像素占比当成熟果数。
没有该类 GT 的层为 `NOT_EVALUABLE`，不能填 0 或合并难类制造高分。

**难点。** 成熟边界可能连续且标注者意见不同；强阴影、曝光、蜡粉反射、遮挡、
背景与品种色差会改变像素颜色。训练增强若随意 hue shift 可能改变标签语义。
同果不同角度的外观差异、class imbalance 及新设备/新种跨域均须覆盖；
不能宣称统一蓝色阈值可适用所有品种。需要先报告人工一致性，判断任务是否可复核。

**成本与资源规划。** 分类除对象定位外增加逐果专家判断、歧义复核和独立成熟测量；
像素成熟分割进一步增加细边界标注。规则/统计基线可在 CPU 离线运行；
未来小 crop CNN 可询价 8–16 GB GPU，整图成熟分割参考 B 档位。
这些不是实测显存/耗时；需记录 crop 总量、类别支持、标注/测量工时、全流程延迟。

**系统关联与首轮判断。** 成熟类别只能作为带定义/来源/version 的独立候选视觉特征，
不自动成为既有模型的成熟曲线、采摘实现率、商品果率或 kg。
在等级/用途/独立参照尚未批准时，C 不应优先于可见检测数据链；
可先研究标签可靠性，不能用 synthetic 类别宣布成熟识别完成。

## 6. 路线 D：视觉观测辅助产量预测

**原理。** 从单图可见计数、成熟比例、观测时序等产生候选代理，关联经批准的
采样范围/覆盖率/频率，以及面积、树龄、品种等非视觉变量；未来在新研究模型中检验
是否提供原面积驱动预测之外的增量信息。可考虑简单分层统计/回归基线、代理特征或
残差模型，所有拟合只用新授权的 train，不能 refit 冻结模型或改 Harvest State。
图像计数受可见率、重复、拍摄面积、采样方式和果实状态影响，既不是全园数量，
也不是直接可采的数量；数量又不能直接确定重量。

**数据及标签。** 除授权的视觉记录外，至少需要：

- 样方/植株/行及其实际面积、抽样设计/纳入概率、拍摄覆盖、每次缺拍和选择理由；
- 同植株跨视角/跨日期对应，采收前后是否相同果实、去重方法、已采/落果/损失记录；
- 品种、树龄、管理/产季/基地 authority 和时间有效版本；可见率/遮挡标定及其不确定性；
- 独立单果/批次重量、计量设备/校准、采收日期/范围、质量/损失口径及 kg source hash；
- 同 Base/season/origin/window 的原面积驱动已保存预测完整 identity/result/model hash，
  独立参考标签 custody 与实际 available_at 证据。

这些只是未来所需条件，本轮没有读取或证明任何真实资料存在。
来源和范围不一致的到厂重量、人工印象、原预测输出或假定单果克数不能充当独立 GT。

**指标。** 在完全相同 common rowset/scope/unit/cutoff 下，对原面积驱动只读快照
与视觉候选报告独立 MAE kg、Bias kg、可定义时的 WAPE、同预测窗口累计误差与成对
误差差值；报告分层退化、独立组不确定区间、视觉缺失导致的覆盖损失。
单位、日期/窗口、质量范围或身份不可对齐则 `NOT_EVALUABLE`。
标签结束后获得可用于经授权评分，视觉特征须在 origin 已可用；事后标注不能倒填
available_at。不存在独立称重和隔离测试，就不能报告预测增益或真实准确率。

**难点。** 偏向易拍植株的非随机采样、全园/单图尺度不一致、重复果、隐藏果、
观测频率差异、果径/单果质量分布变化、采收/落果及商品果边界造成系统误差。
历史 source hash 或早于 cutoff 的日期不自动证明 strict PIT；仓库已有合同明确
历史 available_at 仍有证据限制（见能力审计）。图像在目标采收后可用或用未来标注
拟合过去特征均会泄漏。视觉增益也可能来自更多数据/改变样本范围，需保持公平对照。

**成本与资源规划。** 主要新增成本是纵向采样、现场测量/独立称重、可见率复核、
身份对应和保管未曝光测试，不仅训练 GPU。预算按独立样方×日期×测量工时计算，
对照预测/参考范围不够则不能用更多照片替代。简单回归/统计基线通常可用已有
NumPy/scikit-learn 和 CPU，视觉特征生成另计 A/B/C 推理预算；具体算力取决于样本量
和候选，未运行测量。不引入现有数值模型版本作为本研究模型正式身份。

**系统关联与首轮判断。** 未来只用独立 offline comparison manifest 引用获批准的
Base/Region/Company 与 exact saved run/hash，不按基地名称猜 canonical ID，
不把技术 Company 聚合根当图像所有者，不写生产表/API/FI，也不改已保存预测。
D 当前缺少业务标定与重量 authority，不应作为首次重量实验；先完成可见观测和
采样/称重协议，再决定独立增量研究是否可执行。禁止“计数×经验克数=kg”捷径。

## 7. 数据、标注和资源预算方法

不以任意图片数量、精度目标或论文硬件时间作为本项目验收线。下一次授权后，
先用跨日期/基地/品种/遮挡/光照/设备/角度的批准 pilot 测量标注一致性、实际实例密度
和每图工时，再按独立 group 数及目标区间精度规划样本量；低覆盖层保留缺口。

| 成本项 | 未来须收集的报价/测量依据 |
| --- | --- |
| A 框标注 | 图像整理、每实例框工时、每图检查、歧义和返工、独立复核比例；高密度与空图分别计 |
| B 实例 mask | 与 A 同图的新增边界/object ID 工时、crowd 无法界定率、复核一致性、mask 存储与编码 |
| C 成熟标签 | 专家分类、UNKNOWN 与 disagreement、颜色/设备标定、独立成熟测量及对象对应 |
| D 标定/对照 | 现场采样、频率、身份映射、独立称重/计量校准、测量范围、test custody 与共同覆盖 |
| 算力/存储 | 原图尺寸与字节、派生 crop/mask、训练候选总次数、GPU/CPU 小时、显存/RAM 峰值、授权存储及留存；价格来自实际报价 |

可用预算公式为 `整理工时 + Σ各层(实际图数×测得每图工时) + 复核/返工 + 测量/保管`。
图数不能取代独立样方/会话数，训练/验证/测试不得分享同图、近重复帧或同纵向样方 group。
拟合颜色归一化、采样/重量映射、阈值、后处理只能在对应 train/validation 范围完成。
未授权前不执行 pilot，也不通过安装/调用框架间接自动下载预训练权重。

## 8. 首个实验建议及阶段状态

有条件建议：Owner 先确认“单图**可见蓝莓**检测/计数”的单位与遮挡规则，批准数据来源、
采集/标注/保管和资源范围；完成跨会话/日期/基地、含训练范围外品种/设备/角度的独立
测试设计后，再比较有限检测候选与人工一致性/简单基线。只在 A 的密集计数问题存在
且工时预算允许时，把 B 作为同图增量比较；C 另需成熟参照，D 另需独立采样/称重标定。
最终样本量、主指标、容许偏差、分层退化与延迟门槛由 Owner 预注册。
实际操作与验收顺序遵循 [实验协议](blueberry-vision-experiment-protocol-r1.md)。

| 状态 | 本轮结论 |
