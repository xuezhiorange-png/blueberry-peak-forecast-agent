## 跨渠道审批来源

每项 PR 分别检查：独立技术复审、Owner Ready、Owner Merge。三者不互相替代；合并事实不是事前批准。支持 GitHub Review、GitHub issue comment、原始 ChatGPT 对话、可核验 Codex transcript、其他可信原始记录。

记录包含原始来源定位、稳定消息 ID、完整记录 SHA256、发生/捕获时间、主体与角色、准确 PR/HEAD、动作、范围、独立性、来源真实性、HEAD 绑定及先后关系。SHA256 只能证明捕获字节未变，不能单独证明消息作者、原始时间或审核独立性；这些必须由来源渠道和上下文核实。GitHub COMMENTED 独立技术复审仍为 COMMENTED，不伪装成 APPROVED。共享 GitHub 操作账号不等于实现者与独立评审者必然相同；本轮记录独立评审正文的明确声明及来源限制，不声称获得平台之外的人员身份证明。

仅当原始来源、准确 HEAD、动作范围、独立角色和事前时间全部满足才为 VERIFIED。未取回、二次转述、上下文不足、来源冲突和事后追认分别保留 NOT_FOUND、PENDING_SOURCE_VERIFICATION、PARTIAL_EVIDENCE、CONFLICTING_EVIDENCE、POST_HOC_ATTESTATION。消息“可以”不自动授权合并；“可以ready合并”即使明确包含两动作，也必须证明它之前对应的准确 PR/HEAD 上下文。

## 来源发布与可复现性

新增第五个文件 `v0.18.0-approval-sources-r2.json` 是必要的公开来源捕获：保留本轮重新查询的 GitHub PR/review/comment/CI 元数据及实际 Ready/Merge 事件，另含最小脱敏聊天摘录与读取限制。它使离线 CI 可复现 R2 判定，而不依赖私人聊天权限或实时网络。离线校验的是此次来源捕获及原字节绑定，不宣称 CI 独立重新认证私人平台作者。

运行 `python -m backend.tests.forecast_intelligence.build_v0_18_approval_provenance_r2` 生成 canonical JSON；测试比较确定性输出、来源哈希、R1 六文件 Git 原字节，以及负向审批与门禁输入。新 HEAD CI 必须另行取得，不使用 R1 run #38849776234 代替。

公共记录可用同一命令的 `--capture-public` 选项显式重新读取 GitHub；它不读取私人会话、不补造缺失消息，也不回写原始聊天捕获时间。聊天来源真实性由本轮实际提供方读取核对，离线 CI 不具备重新访问私人会话的能力。

G12 在未合并时检查本轮工作树；存在本 PR 的合并提交后固定核验其 second-parent 交付 HEAD，不把随后另行授权的 main 生产变更误判为历史篡改。负向测试仍要求本轮文件白名单生效。

S6 历史执行源码从固定 `BASE_MAIN_SHA` 的真实 Git blob 核验，与当时的执行源码 SHA256 对照；冻结文档和运行产物继续检查当前原始字节。这样既不降低历史哈希强度，也不把旧运行快照误解为将来永远不能合法修改生产源码。新 HEAD 的当前运行回归仍由本轮 CI 单独负责。
