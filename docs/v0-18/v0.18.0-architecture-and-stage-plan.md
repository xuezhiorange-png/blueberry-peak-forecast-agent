# V0.18 架构、接口约束与阶段计划 R1

所有接口/模块都是设计候选，尚未实现。基线为 v0.17.0，数学 frozen。
不引入第二业务服务、第二算法或完整 IAM 管理平台。

## 1. 信任模型与共享授权层

推荐身份协议方向是 OIDC Authorization Code + PKCE，服务器会话/BFF 持有
token，浏览器使用 Secure/HttpOnly/SameSite cookie，状态改变请求有 CSRF 防护。
不得用 ID Token 作为预测 API 的随意 bearer；适用 API audience/scopes 必须
验证。签名算法 allowlist、issuer/subject/audience/expiry/nonce、redirect URI、
refresh/revocation 与代理信任在 S1 冻结。具体提供方、BFF 实现位置和现有
TrialActorDep 映射未配置，是 S1 P0 输入，不暗示已经存在登录接口。
参考：[OIDC Core errata 2](https://openid.net/specs/openid-connect-core-1_0-errata2.html)、
[RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)。规范参考不替代实际集成安全测试。

TrustedPrincipal = issuer/subject/internal principal/type/org/client/auth context。
ResourceGrant = principal + capability + exact immutable identity/hash +组织边界+
revision/validity/revoked。范围关系来源于服务器批准的授权目录，不是当前
hierarchy registry，不是客户端字符串或仅 source hash。

授权目录可由受信任发布者提供版本化静态配置（合成 pilot 首选）；如真实
用户/关系生命周期要求 DB，必须在 S1 单独审批 schema/migration/管理边界。
不可为方便直接从业务 DB 的名称或创建者字段推断 grant。
身份配置缺失 503，认证失败 401，capability/grant 缺失 403。

安全调用顺序：AUTHENTICATE → CAPABILITY → RESOURCE_GRANT → CANONICAL_READ
→ RECHECK_HASH_AND_GRANT → 既有服务。目录读仅为授权元数据；未经授权 run
不得创建查询其 payload 的 DB session/SQL，Quality 文件读也为零。
S2 source canonical verification 保留，不能因 grant/hash 已通过就跳过。
发生权限撤销或 revision 改变时清理授权 cache、cursor、handoff；正在执行的
只读请求在返回前再检查，不发布撤销后的响应。

授权语义不会自动改变已冻结 S1/S2 business payload/hash；授权 transport 可
增强，但旧 API 行为变更、legacy 路径迁移必须有对应阶段批准和兼容回归。
不存在 resource-granted lookup 时 403 的固定文案与有/无资源相同；对敏感
identity/hash 的存在不做错误区分，审计只保存服务端内部脱敏原因。

## 2. 候选 HTTP 请求/响应设计

这里冻结能力/字段/安全行为，具体 URL 在 S1/S2 兼容审查后批准，不生成路由。

| 能力（候选路径） | 请求 | 输出/前置要求 |
| --- | --- | --- |
| AUTHORIZED_SCOPE（GET /api/v1/business-access/scope） | authenticated session，无 actor 输入 | principal type、授权的 COMPANY/REGION/BASE 显示摘要、capabilities、policy revision，无全局组织列表 |
| AUTHORIZED_SAVED_RUN_LIST（GET /api/v1/business-access/saved-runs） | season、hierarchy、entity、family、origin_from/to、page_size、opaque cursor | 授权过滤后 items、next_cursor、snapshot/revision；无全局总数、数量曲线 |
| VERIFIED_SELECTION_HANDOFF（POST /api/v1/business-access/selection） | 列表返回的完整 identity + expected_source_result_hash、snapshot/revision | 服务端核验的 identity/hash、principal/client-bound signed context、expiry；无经营写入 |

新 envelope 可有 schema_version、status、request_id、policy_revision、data、
safe_code；不是替代现有 ReadResponse/DecisionResponse。Decimal quantity 仍为
字符串；list page 不附每日数量。source_result_hash 不重命名 projection_hash。
状态：READY、EMPTY（仅授权集合确实无结果）、ERROR、AUTHORITY_MISMATCH。
未知/额外字段拒绝，不能将 404 或 forbidden 当 EMPTY。

完整选择十字段：source_kind、forecast_family、run_id、hierarchy_level、entity_id、
target_season、origin_date、baseline_id、policy_version、expected_source_result_hash。
canonical verifier 必须校验 summary/daily/lineage。未知模型不匹配其他 family。
列表 item 是保存记录范围，不是当前 registry 展开的新预测；同名 entity
跨季/family不合并。rerun 是独立授权对象，不自动替换原 run。

分页详细约束见 scope；catalog snapshot 是已批准的最小元数据快照，不是
从未经授权全库响应生成。authorized WHERE/filter 与 keyset 必须在 limit 前。
元数据权限/hash 不能证明 payload 完整；交接和最终 read 再校验 canonical。
目录可能滞后：授权 item 对应记录损坏/删除时 fail closed，可给已授权用户
409/404 并重选；不得在列表里替换另一 record。全局 latest 不暴露，用户明确
选择排序后的结果；即使目录只有一条也不默默跨 family 选取。

Handoff token 是服务器签名的短期完整性 context，不授予新权限，浏览器不持有
签名密钥。缓存键包含 principal/client/grant revision/full identity/hash；响应
不得共享到另一个用户；敏感缓存 private/no-store，日志与 URL 不含凭据。

| HTTP | 候选固定语义 |
| --- | --- |
| 401 | 认证缺失/失效，响应不含资源信息 |
| 403 | 无 capability/grant，包括未授权或不存在的请求 identity，同样 denial，先于业务读取 |
| 404 | 仅在准确 grant 已有效验证后发现其绑定保存记录已不存在 |
| 409 | 源 hash/完整身份/目录 revision 冲突，清理结果并重选；不自动最新替换 |
| 413 | 显式 body limit；沿用 S2 131072 bytes，不静默截断 |
| 422 | 输入/分页/cursor非法，无 raw input/私有路径回显 |
| 503 | 身份/授权配置、DB、服务不可用，脱敏且允许重试 |

现有 S1 查询 8192 bytes、S2 20 scenarios×15 days、workforce ≤1000000、
Decimal ≤64 chars 不放宽。三种成本 ID/hash 从冻结 S5 获取，必须显式选择。
模拟 POST 无持久化经营动作；仅授权层审计或选择 context 元数据不能悄悄变成
预测写入、数据库创建新 forecast 或实际采收导入。

## 3. MCP 与前端兼容

八工具不扩增，仍直接调用 S1/S2。独立 HTTPS MCP ASGI 与 legacy 分信任域。
服务凭据继续由服务端持有，最终用户身份用受信任 transport delegation，
禁止 identity/source_system/actor 工具参数授权。用户 ∩ client ∩ exact grants
同时成立；Quality grant独立。会话/取消/并发不得串 principal。
没有适配的委托 token 能力时保持 service-account-only，用户权限验收 BLOCKED。
正式接入豆包客户端需要协议、audience/issuer、撤销和调用方识别实际验证，
不声明现有 X-Forecast-Intelligence-Key 自动升级为 OAuth/用户身份。

Dashboard 保留五页与 S4 tokens，增加正常授权列表/筛选/选择路径，不改变
计算、图表数量、样本含义或 Trial。advanced输入仍要资源授权，不能旁路。
Auth失效/撤销时取消请求、清理受影响数据与选择；列表快速切换、hash漂移、
迟到请求、logout、tab刷新不得把 A 用户结果给 B。选择验证失败不提交新身份。
模拟输入 revision 改变即隐藏旧 ranking；不持久化经营动作，不在浏览器重算。

授权、merge + main CI；完成一阶段不暗示下一阶段。下列 allowed paths 是未来
