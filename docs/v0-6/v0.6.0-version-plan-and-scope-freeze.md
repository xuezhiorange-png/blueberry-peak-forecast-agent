本文件只冻结 V0.6 的版本目标、数据合同、Slice 顺序、验收标准、非范围和发布边界。
它不实现任何 Slice，也不授权生产代码、模型、数据库迁移、天气 provider 接入或部署。

## 1. 版本目标

V0.5.3 已发布面积驱动的实验性预测产品，但它还不能回答一次预测在真实发生时到底看到了
什么。V0.6 的唯一主线是建立可回放的 Point-in-Time（PIT）闭环：

    PIT 已知信息
      → Forecast
      → immutable forecast snapshot
      → 后续 Actual Harvest / Realized Weather
      → Forecast vs Actual
      → prospective validation
      → weather / phenology incremental-value assessment

每一次评价都必须能够回答：预测创建时刻是什么；使用了哪个面积版本；当时可见的历史采摘
是什么；当时真实可获得的天气预报是什么；当时记录了哪些物候；模型输出和 hash 是什么；
后续真实采摘和天气是什么；误差是多少；天气或物候是否带来可复现的增量价值。

V0.5 的冻结基线继续有效：

    V0_5_RELEASE=v0.5.3
    V0_5_MAIN_SHA=c0daf23b3d8d5c3b43733824b95024c44b9c220b
    TOTAL_MODEL=BASE_AWARE_BASELINE_R1
    TEMPORAL_REFERENCE_MODEL=AREA_DAILY_RIDGE_V1_FROZEN_REFERENCE
    MODEL_STATUS=EXPERIMENTAL

V0.6 不重新训练或调参 V0.5 模型。V0.6 的价值在于验证信息边界和真实预测能力，而不是
预设天气一定有效或把研究结果直接提升为生产模型。

## 3. S1：PIT 数据基础设施合同

### 3.1 forecast_run_snapshot

S1 必须定义 append-only、immutable 的预测快照。它保存预测创建时的完整输入和输出，后续
actual 到来后只能追加评价，不能改写原 snapshot。

最低字段：

    forecast_run_id, forecast_created_at
    base_id, target_season, forecast_start_date, forecast_end_date, target_area_mu
    forecast_mode, model_status
    total_model_id, temporal_model_id, model_artifact_hashes
    prior_history_season, prior_history_quantity_kg, prior_history_coverage_status
    prior_history_source_hash, prior_history_identity_mapping_hash
    area_revision_id, weather_snapshot_ids[], phenology_observation_ids[]
    input_snapshot_json, input_snapshot_hash
    predicted_season_total_kg, predicted_daily_curve
    single_day_peak, rolling_7day_peak, result_hash, warnings

    APPEND_ONLY=true
    IMMUTABLE=true
    DETERMINISTIC_HASH=true
    HINDSIGHT_INPUT_MUTATION=false

input_snapshot_hash 必须覆盖所有进入预测的 PIT 输入身份、版本和覆盖状态，不能只 hash
用户请求而漏掉面积、历史数据、天气或物候 snapshot。

### 3.2 area_revision

面积必须版本化，并按生效范围和记录时间可追溯：

    area_revision_id, base_id, season, area_mu, area_type
    effective_from, effective_to, recorded_at, source, basis
    supersedes_revision_id, hash

area_type 至少包括：REFERENCE_AREA、ACTUAL_PRODUCTIVE_AREA、PLANTED_AREA、PLANNED_AREA。
当前《基地位置亩数.xlsx》只能登记为 REFERENCE_AREA，不得自动升级为
ACTUAL_PRODUCTIVE_AREA，不得用未来补录面积改写已完成的 forecast snapshot。

### 3.3 weather_forecast_snapshot

这是 V0.6 的正式新增语义：保存预测创建时真实可获得的天气预报，而不是事后重分析或
realized weather。

最低字段：

    weather_snapshot_id, provider, base_id, location_id
    issued_at, fetched_at, valid_at, forecast_horizon_hours
    temperature_min, temperature_max, temperature_mean
    precipitation, relative_humidity, solar_radiation, wind_speed
    raw_payload_reference, raw_payload_hash, normalized_payload_hash

provider 未提供的字段可以为 null，但不能用另一个数据源静默补值。

    FORECAST_TIME_WEATHER_ONLY=true
    REALIZED_WEATHER_IN_FORECAST_SNAPSHOT=false
    ERA5_REANALYSIS_IN_FORECAST_SNAPSHOT=false
    HINDSIGHT_WEATHER_IN_FORECAST_SNAPSHOT=false

如果执行时尚未接入合法 provider，只能完成 schema、persistence 和 contract；不得伪造
weather snapshot，也不得用 ERA5-Land realized/reanalysis 冒充 as-issued forecast。

### 3.4 realized_weather_observation

事后真实天气单独保存，不能与 weather_forecast_snapshot 混表或混用：

    base_id / location_id, observation_time
    temperature, precipitation, humidity, solar_radiation, wind
    source, source_hash

    FORECAST_WEATHER != REALIZED_WEATHER

### 3.5 phenology_observation

物候可以一季多次观测，必须保留观测和记录时间：

    observation_id, base_id, farm_id(nullable), season, phenology_stage
    observed_at, recorded_at, source, source_reference
    quality_status, notes, payload_hash

只有 recorded_at/known_at <= forecast_created_at 时，观测才能进入该次 forecast snapshot。
事后物候只能用于诊断或后续 PIT 评价，不能倒灌旧预测。

### 3.6 actual_harvest

S1 必须先审查并复用仓库已有 actual-harvest staging/persistence，不得创建第二套平行事实
框架。最低能力必须表达：

    base_id / farm_id, harvest_date, quantity_kg
    source, revision_or_event_id, observed_at, recorded_at
    known_at / visible_at, hash

actual 的后续修订应形成新 revision/event 并可追溯，不能修改已经保存的 forecast input 或
result。

## 4. 统一 PIT 可见性规则

统一规则：

    record_visible_at(record, forecast_created_at)
        iff record.known_at <= forecast_created_at

面积、历史采摘、物候以及其他输入只有在预测创建时已经可见才可以进入 snapshot。

天气还必须满足：

    weather.issued_at <= forecast_created_at
    AND snapshot 在 forecast_created_at 前已真实可获得

以下全部禁止：hindsight weather、hindsight phenology、hindsight area revision、future
actual harvest、事后补录污染旧 forecast、用 realized weather 伪造 as-issued forecast archive。

每个 snapshot 应能审计 known_at/recorded_at/issued_at 和对应 hash，而不是只保存最终数值。

## 5. S2：Shadow Forecast 与天气采集

S2 从真实运行时刻开始积累未来可回放的预测历史，不回填历史上不存在的 forecast archive。

    FORECAST_MODE=SHADOW
    MODEL_STATUS=EXPERIMENTAL
    TOTAL_MODEL=BASE_AWARE_BASELINE_R1
    TEMPORAL_REFERENCE=AREA_DAILY_RIDGE_V1_FROZEN_REFERENCE
    MODEL_RETRAINED=false
    MODEL_TUNED=false

每次 shadow run 必须依次：

1. 选择并冻结当时有效的 area revision；
2. 加载当时可见的 immediate-prior history；
3. 保存当时真实可获得的 weather forecast snapshot；
4. 保存当时已经记录的 phenology observations（如有）；
5. 生成完整 input snapshot 和 hash；
6. 生成完整 forecast result 和 result hash；
7. 后续只追加 actual/realized observations，不修改本次 run。

必须支持 single-base run 和 39-base batch run。第一版允许最小 manual batch 或已有 scheduler，
但不能以手工运行作为缺少 immutable snapshot 的理由。

V0.6 weather scope：

    V0_6_WEATHER_SCOPE=POINT_IN_TIME_FORECAST_WEATHER_CAPTURE_AND_INCREMENTAL_VALUE_EVALUATION
    FORECAST_TIME_WEATHER_CAPTURE=true
    REALIZED_WEATHER_CAPTURE=true
    WEATHER_FORECAST_VS_REALIZED_EVALUATION=true
    WEATHER_INCREMENTAL_VALUE_ABLATION=true
    WEATHER_MODEL_RETRAINING=false
    WEATHER_MODEL_PROMOTION=false
    WEATHER_AWARE_PRODUCTION_MODEL=false

这表示 V0.6 要验证天气是否有真实增量价值，不表示天气一定有效。

## 6. S3：Forecast vs Actual 评价

S3 建立 Forecast → Actual → Error 闭环。forecast 与 actual 至少按 base_id、target_season、
date 对齐；产季进行中必须支持 AS_OF_DATE，只评价截至该日已经发生且可见的范围。

必须计算：

| 输出 | 指标 |
| --- | --- |
| Season total | MAE、WAPE、Bias、MAPE（安全分母） |
| Daily | daily MAE、daily WAPE、daily Bias |
| Single-day peak | peak quantity error、peak date error |
| Rolling 7-day peak | 7-day cumulative error、7-day start-date error |

原始 forecast snapshot 的 input hash、result hash、预测值和 warnings 必须保持不变；Actual
到来只追加评价结果或新的 actual event。

S3 同时评价 weather_forecast_snapshot 与 realized_weather_observation：temperature MAE/bias、
precipitation error、GDD forecast error（仅当 GDD 定义已独立冻结），以及 provider 实际
支持的 D+1、D+3、D+7、D+15 horizon。

## 7. S4：Prospective Validation 与天气增量价值

S4 只接受真正 PIT 保存的预测：

    forecast_created_at < actual_harvest.observed_at

必须保留 V0.5 historical-only baseline：

    MODEL_A=AREA_PLUS_HISTORICAL_HARVEST

Model B / diagnostic B 只能使用真实 as-issued、在 forecast time 可得的 weather snapshot：

    MODEL_B_OR_DIAGNOSTIC_B=AREA_PLUS_HISTORICAL_HARVEST_PLUS_FORECAST_TIME_WEATHER
    REALIZED_WEATHER_AS_MODEL_INPUT=false

若没有足够 PIT 样本或尚未训练 weather-aware model，可以先做 incremental signal analysis、
feature ablation、temporal correlation 或 oracle-free diagnostic；不得用 realized weather
作为 Model B 的预测输入。

必须回答：forecast-time temperature 是否改善 peak timing；forecast-time GDD 是否改善
temporal alignment；降雨是否对 harvest timing/quantity 有稳定增量关系；forecast-time weather
是否改善 daily WAPE、peak-date MAE、rolling-7-day start-date MAE；改善是否跨 Base 一致；
是否足以支持 V0.7 weather-aware model。

整体至少报告：SEASON_TOTAL_WAPE、DAILY_WAPE、SINGLE_DAY_PEAK_QUANTITY_WAPE、
SINGLE_DAY_PEAK_DATE_MAE、ROLLING_7DAY_PEAK_WAPE、ROLLING_7DAY_START_DATE_MAE、BIAS，
并分 all available Base、stable-history Base、coverage-limited Base 报告。

    WEATHER_INFORMATION_ADDS_SIGNAL=
    WEATHER_INCREMENTAL_VALUE_MATERIAL=
    WEATHER_AWARE_V0_7_JUSTIFIED=

这些值必须由 prospective evidence 决定，不能由版本计划预设。

## 8. 能力与生产就绪边界

V0.6 完成不自动把任何输出标为生产就绪。S4 必须分别裁决：

    SEASON_TOTAL_PRODUCTION_READY=
    DAILY_CURVE_PRODUCTION_READY=
    SINGLE_DAY_PEAK_PRODUCTION_READY=
    ROLLING_7DAY_PEAK_PRODUCTION_READY=

V0.5 的约 37.9% known-base total WAPE、约 69.4% daily WAPE、约 22.23 天 peak-date MAE、
约 20.77 天 rolling-7-day start-date MAE 只作为基线和限制披露，不构成 V0.6 新验收阈值，
也不等同于准确率生产批准。

## 9. V0.6 非范围

以下内容明确不进入 V0.6：

- boosting、deep learning 或大规模模型 leaderboard；
- 自动 weather-aware model training 或自动 model promotion；
- 自动 phenology model training；
- multi-factory routing、peak shaving、factory capacity optimization；
- cold-storage integration；
- commercial UI、recommendation engine、multi-agent expansion；
- historical area archaeology；
- 修改 V0.5 模型、authority、结果 hash 或现有生产合同；
- 未经授权的天气 provider 采购、生产部署或公网服务；
- 用事后 realized weather/phenology 伪造历史 as-issued archive。
