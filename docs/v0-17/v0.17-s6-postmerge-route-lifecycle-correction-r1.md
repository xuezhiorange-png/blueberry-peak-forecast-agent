## Root cause and minimal proxy change

Original proxy performed an independent APIRequestContext `route.fetch()` and
then `route.fulfill({response})`. The Trace shows business assertions finishing,
followed by pending fetch completions attempting fulfill during page/context
fixture cleanup. Routes were already handled, and page fixture teardown exceeded
30000ms. A detached fetch/fulfill response lifecycle outlived route ownership.
This is a test proxy defect, not evidence of a production cancellation defect.

The proxy now passes only the target URL to `await route.continue({url})`.
It does not override method, body or headers, create an independent API fetch,
or attempt a second route action after receiving the response. The browser owns
response cancellation. Teardown retains `unrouteAll({behavior:"wait"})`.
There is no route-error catch, ignoreErrors, fixed sleep, skipped test, removed
assertion, raised timeout or production cancellation change.
