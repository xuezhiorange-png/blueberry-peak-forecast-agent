## One service authority / API mapping

The dedicated client permits only the six existing
`/api/v1/forecast-intelligence/{overview,curve,hierarchy,uncertainty,attribution,quality}` GET paths
and `/api/v1/decision-support/{business-loss,simulate-capacity,compare-capacity-scenarios}`.
Only the latter two simulation paths use POST. No backend endpoint, business algorithm,
MCP entry, database schema or authorization rule is added or modified.

Zod contracts follow the real S1/S2 Pydantic fields. Unknown fields are rejected.
Source, read projection, adapter, scenario, engine and comparison hashes remain distinct.
Full forecast identity and expected source hash are checked on every forecast response.
Hierarchy identity, source policy/baseline, row identity, unique ordered dates and counts are checked.
Response policy is capability-specific: hierarchy reconciliation, uncertainty and attribution
policies are not confused with the underlying forecast's source policy.
Simulation and comparison validate nested saved-forecast bindings, dates, scenario membership,
cost/planning authority, engine-result hashes and the server's ranking/result references.
The browser does not recompute cryptographic engine outputs or business results.

Authoritative quantities stay Decimal strings. Input quantities are bounded, nonnegative decimal
strings; workforce is a strict bounded integer. Unsafe numeric run IDs are rejected rather than
rounded. Plotting converts values only into transient geometry. KPI formatting may remove
insignificant trailing zero characters or display a date as MM-DD; the full original value is
retained in the title, typed response and authority details. This is not quantity arithmetic.
Tooltips and auxiliary tables expose original strings. Long historical metric/utilization strings
use an explicitly labelled text excerpt (not rounding) with the full value in the accessible label,
title and expandable exact-value details. Excerpts never become request or authority values.

## Saved-run selection and request state machine

Normal business discovery / trusted handoff is **not available** in the current backend.
The selector explicitly explains this gap; there is no fake latest list, legacy LIST fallback,
automatic run choice, uploaded forecast curve or client-generated hierarchy.

Advanced technical selection requires all ten identity/hash fields. It calls the real S1 curve
endpoint, verifies the response, and atomically commits only a nonempty READY/PARTIAL curve.
Failed verification leaves the previous valid context unchanged. Input identity is not an
authorization grant. HTTP still has coarse actor permissions, not proven user/base isolation.
Full identities are held in page memory, not localStorage. No authentication secrets are stored
in browser state, logs or URLs. Necessary selection parameters use the existing GET contract.

`AbortController`, request generations and validated context keys reject cancelled/late results.
Run changes clear the selected date and remount simulation drafts/results. All modules have
independent state. Quality is keyed to its own historical authority, never to the selected base.
App navigation and run replacement warn before abandoning edited scenario drafts; beforeunload
protects document navigation. Browser-history navigation can discard in-memory drafts and does
not provide durable draft persistence; it never makes an old calculation valid for new inputs.

## Page and state contracts

The overview's four KPI order is fixed: D1–D7 total, D1–D15 total, saved-curve peak date,
peak daily quantity. These come from the server. H7 is not D7 alone; historical origins are
not called today's future. High-load dates retain server order and are descriptive, not alarms.
Missing child coverage is not zero; contributions remain NOT_AVAILABLE without a server contract.

Forecast H1/H3/H7/H15 controls only project the returned legal daily sequence. They do not
create cumulative KPIs. Date buttons, chart focus and the daily table share the selected date.
Missing dates break segments, without interpolation, extrapolation or zero filling.

Upper80/90 and the Operational Peak run's M1 attribution remain NOT_AVAILABLE. They never fall
back to POINT. A future attribution READY payload needs a reviewed schema; no generic feature
importance or synthetic contribution chart is substituted. Point is not proven P50; planning
bounds are not proven quantiles. Model attribution is not causal explanation.

Every page uses independently managed LOADING, READY, EMPTY, PARTIAL, NOT_AVAILABLE, ERROR,
AUTHORITY_MISMATCH and NO_CURRENT_ACTUAL presentations. Some states are deliberately not
admissible as successful data for a capability (for example current bound attribution READY).
Null is shown as unavailable, never zero. 404 is an error, not EMPTY. 409 clears affected
results and offers re-verification. 503 offers retry. 401/403 use fixed copy without resource
existence or server-error details. Normal business unavailability is not a transport failure.

## Explicit scenario interaction

Each scenario starts with blank identity/version and blank per-date capacity inputs.
Cost selection has no default. The three pinned S5 synthetic contracts are checked through
Business Loss exposure before execution. There is no user cost-coefficient override.
Both DIRECT and WORKFORCE_DERIVED are supported with mutually exclusive fields.
The latter requires explicit workforce and productivity; their product is never calculated
in the browser. An optional same-day buffer is not storage inventory and does not carry forward.
Initial backlog is fixed at zero, with no editor.

Every saved date is edited explicitly. The optional copy-all action requires confirmation
listing the target dates and copies request inputs only. Limits remain 20 scenarios, 15 days,
1,000,000 workforce, 64 characters per quantity and 131072 UTF-8 request-body bytes.
Incomplete child coverage cannot enter simulation. Short saved windows are labelled by their
actual number of dates, never filled out to fifteen days.

Manual submission calls S2. Results retain daily demand, handling provenance, processed quantity,
opening/closing backlog, daily overload, effective capacity, aggregate totals, loss and hashes.
Daily overload is not closing backlog; cumulative shortfall is not ending backlog.
Utilization retains exact numerator/denominator and the server's Decimal50 HALF_EVEN derived
representation and rounding flag. No utilization arithmetic is performed in the browser.

Any input, cost or planning change aborts work, increments the input revision and removes prior
results/rankings. A successful current response alone clears staleness. Comparisons use only S2's
returned ranking, never a browser sort. Synthetic loss uses SYNTHETIC_LOSS_UNIT, not money,
savings or ROI. Ranking is descriptive under given conditions, not optimization or scheduling.
