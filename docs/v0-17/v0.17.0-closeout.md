## V0.17 实际建立的产品能力

### 一套服务、三个消费表面

冻结 V0.16 引擎 → Forecast Intelligence Service / Decision Adapter →
HTTP API、独立 MCP；Dashboard 通过 HTTP 消费相同服务。API/MCP/浏览器
不各自建立预测、积压、损失或排名算法。

S1 提供 overview、curve、hierarchy、uncertainty、attribution、quality 六项
GET。读取 explicit saved run 的完整 family/run/entity/season/origin/baseline/
policy/hash，canonical integrity fail-closed，无 latest 猜测、跨 run 拼接、
补零、推理或新预测。BASE 为原子保存记录，REGION/COMPANY 保留历史保存
hierarchy snapshot，不用当前 registry 改写历史关系。H7 是 D1..D7 前缀；
H15 是 D1..D15。短窗口保持 PARTIAL/null，缺 child 不当零。

S2 GET business-loss 暴露显式选择的三个冻结 synthetic cost contracts，
无 scenario 不生成损失金额。POST simulate-capacity / compare-capacity-scenarios
是无持久化情景计算，不是经营写入。服务器读取 saved curve、显式 daily
DIRECT 或 WORKFORCE_DERIVED、显式 productivity、同日 buffer、initial backlog=0，
直接调用冻结 S5/S6。BASE adapter 的 scope hash 是明确标记的原子范围绑定，
不是捏造 hierarchy registry hash；上海日期午夜 anchor 不是 issuance timestamp。

保留来源、projection、adapter、scenario、engine result、comparison hash 的
区别；权威数量保持 Decimal strings。仅利用率的 numerator/denominator
派生表示允许冻结 Decimal50 HALF_EVEN，不能反馈数量、损失或排名。
日过载不是跨日积压，累计 shortfall 不是 ending backlog。S6 的规划需求与
capacity-gap loss 不是 S5 historical actual-vs-forecast scoring。

### 八个 MCP 工具

get_forecast_overview、get_forecast_curve、get_hierarchical_forecast、
get_forecast_uncertainty、get_forecast_attribution、get_forecast_quality、
simulate_capacity、compare_capacity_scenarios。没有第九个 Business Loss 工具。

Quality grant 独立。拒绝发生在读取/业务执行前。

旧 MCP 保留，不能将新入口 grant 解释为旧入口网络已隔离。Service account
不是最终用户 ACL；HTTP 粗粒度 actor 权限也不是逐用户/逐基地资源授权。

### 五页 React Dashboard

总览、预测、影响因素、产能模拟、预测质量，路径为 /dashboard/overview、
/dashboard/forecast、/dashboard/attribution、/dashboard/capacity、/dashboard/quality。
采用 S4 pine/light B2B 设计、四 KPI、真实 SVG 日曲线和同源数据表、日期联动、
高级完整身份核验、逐日产能编辑、显式成本选择、手动提交、服务器条件排名、
请求取消/迟到拒绝/过期结果失效。旧 Trial 路径和历史合同保留。

五页八状态按模块独立，Forecast READY 不代表上界/归因 READY。无授权业务
发现来源时提示“请选择已保存预测”，不伪造最新列表。Quality 不随选定的
Operational Peak 实体改名为该实体实际准确率。
