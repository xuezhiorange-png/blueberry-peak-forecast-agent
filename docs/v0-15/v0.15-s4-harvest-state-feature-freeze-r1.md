## 定义与日期边界

`HARVEST_STATE_V1` 严格只有四个模型输入，单位 kg：

| 特征 | 允许的日期 |
|---|---|
| past_7d_harvest_kg | origin 本地日期前 7 个完整 calendar business days |
| past_14d_harvest_kg | origin 本地日期前 14 个完整 calendar business days |
| past_28d_harvest_kg | origin 本地日期前 28 个完整 calendar business days |
| season_to_date_harvest_kg | 冻结 business season start 至 origin 前一天 |

origin 为 Asia/Shanghai 17:00；当天完整采收不假定已经可知。
所有动态输入必须满足 `business_date < origin local date`。
用 Decimal（precision 50）累加，不拟合 scaler、encoder 或 imputer。
没有趋势、比例、峰值、Base ID、天气或其他特征搜索。

只接受 `VALID_OBSERVED` 和 quantity 精确为 0 的 `REAL_ZERO`。
缺日、UNKNOWN、PARTIAL_SUBTOTAL、MISSING、CONFLICTING、INVALID 都不能成为完整窗口。
缺任何一个 calendar day，整个对应聚合值为 NULL，记录 missing_count；不缩短窗口。
season start 之前的日期不是零；season-to-date 在 season start 当日为空和（0），
这是没有历史日的数学总和，不是把缺失采收补零。该 origin 仍因 prior windows 不完整而排除。
四个 missing_count 只用于 audit/admission，不能作为额外模型特征。

历史 business boundary 直接复用 S1/S2 authority：2023–24 和 2024–25 从 7 月 1 日开始；
2025–26 从 7 月 22 日开始；都结束于次年 4 月 15 日。没有扩展 business season。

这些是从 source-pinned 历史 projection 与 S2 feature 文件计算得到，不是硬编码准入结果。
结构性预期仅用于核对。每个 admitted Base×Season 的最前 28 origins 因历史不足被排除。
prior-7 / prior-14 / prior-28 不完整 origin 数分别是 532 / 1,064 / 2,128；
season-to-date 不完整为 0。完整样本存在于三个 split，不重切时间。

一个 origin 只计算一次四值 vector，未来 D1–D15 共享该 vector。
完整性只是 date-bound calendar completeness，绝不是 historical available_at 证明。
`STRICT_PIT=false`、`HARVEST_STATE_EVIDENCE_GRADE=RETROSPECTIVE_DATE_BOUND`、
`RETROSPECTIVE_AUTHORITY_USED=true`、`PROSPECTIVE_CLAIM_ALLOWED=false`。
2025–26 仍是已暴露 OOT，2026–27 仍保留独立 prospective validation。

## 物理隔离和来源

只读已有冻结的 33,033 条历史逻辑记录及 S2 Base10 feature 文件。
先检查整个输入 season envelope；若出现 2026–27，整批拒绝，不过滤后继续。
不打开 S2 label_zone、Weather8、S3 models/predictions 或生产数据库。
原始 projection、S2/S3 artifacts、V0.14、冷库服务全部保留不修改。

materializer 在受控私有输出建立 feature_zone 与 audit，目录 0700、文件 0600。
feature 文件仅含四个聚合值、missing counts、row identity、split、grade、policy/hash 和
过去实际消费记录的 lineage。没有逐日 quantity 明细、未来 target hashes 或 label_hash。
原始 source_hash 与仅由消费过的过去记录组成的 canonical receipt hash 一起绑定来源；
整季 projection hash 放在独立 source audit/manifest，不放进每个 feature row。
这防止未消费的当天/未来记录修订改变 feature bytes。

测试实际修改当天、D+1、D+7、D+15、季末 actual 和 future source hash，
验证 vector hash、row hash、完整 artifact bytes 不变；修改 D−1，四个值和 hashes/bytes 都必须变化。
同样在每个 split 的一个真实历史完整 origin 执行 mutation proof，只公开布尔结果。
没有读取或输出 2026–27 actual，没有看模型误差，没有自动删除真实极端采收。

## 操作与确定性

用 `python -m scripts.materialize_v0_15_s4_harvest_state materialize`，显式传入
`--dataset --projection --private --public`。私有绝对路径不写入公开配置/证据。
同一输入分别在两个 fresh Python processes 输出到新的私有目录，再用
`verify-replay --first --second --public` 比较全部 JSON 文件的 bytes/hashes。
不覆盖旧产物；不同 bytes 写向已有路径会 fail closed。

公开 evidence 只提交 aggregate counts、contracts、source hashes、sanitized manifests 和
leakage/replay receipts；没有 Base 级特征值、逐日产量、私有坐标、凭据或模型文件。
materialization manifest 保持 immutable；replay verification 使用单独 supplemental manifest
绑定，不回写原始 materialization manifest。本地测试与 exact-head CI 分开报告。
