# V0.15 S5: fixed Ridge Harvest State incremental-value experiment

Owner authorization is limited to M0 (Base10) and M1 (Base10 plus the four
frozen Harvest State V1 features), on the S4 complete common rowset. This is
retrospective research, not strict PIT, pristine blind testing or production
approval. No dependency, Weather8, tree-model, S1/S2/S4 authority, prospective
runtime or scheduler change is authorized.

The base is `33b51a7bbe08b4dc11cf33d01b3bcb95398ef102`. TRAIN / VALIDATION /
EXPOSED_OOT remain 2023–2024 / 2024–2025 / 2025–2026. The last season is already
exposed; 2026–2027 actuals are prohibited. S3 metrics are not the comparator.
Both models are refitted on this experiment's identical target rows.

## Custody and execution

The operator is `scripts/run_v0_15_s5_harvest_incremental.py`. Run with the
existing locked environment and `OPENBLAS_NUM_THREADS=1`, `OMP_NUM_THREADS=1`,
`MKL_NUM_THREADS=1`. The arguments `--dataset`, `--harvest-state`, and `--output`
refer to private operator paths; do not publish their values.

Run stages A, B, FINAL, SCORE in that order, each in a fresh process:

1. A freezes source/config/input hashes, verifies feature artifacts and common
   keys, opens only TRAIN labels, fits both models and persists Validation
   prediction files and their immutable seal.
2. B verifies seal and actual prediction file hashes before opening Validation
   labels. A durable consumed marker precedes label access. Score once.
3. FINAL uses TRAIN plus VALIDATION irrespective of the observed scores. Refit
   the same two fixed models and persist OOT predictions and seal before OOT
   label access. The scaler is fit only on this authorized final-fit set.
4. SCORE verifies the OOT seal, creates a consumed marker and then opens OOT
   labels once. Any scoring exception invalidates the run; no hidden corrective
   rerun is allowed. Owner reauthorization is required after invalidation.

Execute an independently authorized deterministic replay of the unchanged
contract in a second fresh output directory. PUBLISH compares canonical
prediction, metric, delta, breadth, robustness and classification bytes across
the two runs. Independent real-time seal timestamps are custody receipts, not
deterministic model outputs, and are explicitly excluded from byte equality.

## Frozen comparison

Origins are 3,705 / 5,412 / 8,775; target rows are 55,575 / 81,180 / 131,625.
Final fit has 136,755 target rows. M0 has 10 features and M1 has 14. No feature
search, alpha sweep, weighting, subsampling or deduplication is permitted.
Authoritative Ridge uses alpha 10, population-standard-deviation scaling,
unpenalized intercept, scale 1 for zero variance, `numpy.linalg.solve` and
nonnegative predictions formatted to 12 decimal places. Scoring reuses S3's
Decimal implementation, including earliest peak ties and the whole-metric
undefined curve-shape rule if any origin has nonpositive actual/predicted total.

Error delta is M1 minus M0. SUPPORTED requires negative H7/H15 daily WAPE
deltas in both seasons, improved actual-kg share strictly greater than one half
in all four breadth checks, and negative H7/H15 deltas after removal of the two
largest positive H15 error-reduction contributors. Rank ties use private Base
ID lexical order, frozen before scoring. Remove each entire Base, not selected
rows. NOT_SUPPORTED requires all four primary deltas nonnegative and no stable
two-horizon leave-top2 improvement. Missing denominators, mixed directions or
failed breadth/robustness support are INCONCLUSIVE. No minimum improvement
percentage is invented.

## Privacy and stop boundary

Feature/label source files remain immutable and physically separate. Frozen
label hashes are inspected from the manifest up front; label file bytes are
opened/hash-checked only at the authorized stage. Weather files, raw harvest
projections, SQL and current-season actuals are never accessed.

Daily actuals/predictions, Harvest State numbers, private Base identities,
coefficients, scaler values and model artifacts remain private. Public reports
contain only aggregate metrics, contracts, hashes, seals and sanitized custody
receipts. Public readiness denotes contract execution, not positive model
results or production approval. The PR remains Draft; Ready, Merge and any next
stage require separate owner authorization.
