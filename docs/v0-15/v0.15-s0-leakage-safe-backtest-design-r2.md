# V0.15 S0 R2 — 历史回放与标签隔离设计

状态：审计设计，不是训练、回测或上线授权。S1–S6 未授权。

## 两类证据并行

历史 operational archive 回放与 V0.14 prospective cohort 并行。前者研究历史性能，后者同时检验真实获取、运营和未来性能。本轮不读取或修改 V0.14 私有运行状态，不连接生产服务器。

ERA5/ERA5-Land 是事后 proxy，不得进入历史 as-issued 特征通道。后来生成的 reforecast 也不是当时 operational forecast。历史归档的 issue 时间不是历史实际可获取时间；今天 retrieval 的 receipt 不能回填成历史 known_at。

## PIT admission

每条输入同时保留 event/effective time 与 information_available_at。只有 available_at <= forecast cutoff T 才可入预测区。历史面积追认、identity 修订不能因为 effective 日期早就视作当时已知。缺少 available_at 的记录为 PIT 未闭合，不用文件 mtime 代替。

天气保存 class/model、stream、type、expver、model cycle、resolution、issue、step、valid time、parameter、source 和 retrieval receipt。还须有历史 dissemination/publication 或当时 acquisition 证据，满足 issue <= T、历史 available_at <= T、issue < valid。

若只能证明 operational archive 内容、不能证明历史 availability，降级为 `OPERATIONAL_ARCHIVE_REPLAY_WITH_AVAILABILITY_ASSUMPTION`，不能称严格 production-like PIT。模型 cycle 的实际升级日期保留，不静默 harmonize。

run-selection policy 必须在结果前冻结：业务 cutoff、eligible cycles、完整性、run-age、同一 run 字段一致性、缺失 fail-closed。不能看真实天气再挑 run。V0.14 Weather8 需要 84 个 instantaneous steps 和 256 个字段；TIGGE 的 6h 时效和 net solar ssr 不能直接替代 3h endpoint surface 与 downward ssrd。

## 切分及封存

不预定 TRAIN/VALIDATION/BLIND_TEST 年份。先核验覆盖、信息可用时间和历史消费记录，再经后续 Gate 冻结 Base、origin 和时间切分。已经用于 V0.5/V0.8/V0.13 开发或评估的历史季不能重新标为 fresh blind。

blind 可暴露 Base、Season、origin、日期范围和 availability mask，不暴露数量、累计或峰值。availability mask 的构建也须记录独立 custody。

流程：forecast-time features → frozen model prediction → ordered target rows/package → SHA256/direct seal → custody verification → scorer-only unlock → locked scoring。seal 绑定请求、训练 cutoff、模型、policy、authority、weather provenance、目标 keys 和预测 hash。解锁后永久记录 `BLIND_TEST_CONSUMED=true`，不得调参后重称新 blind。

D1–D15 的业务日期定义尚需后续冻结；不得静默等同 V0.14 lead 0..14。split、forecast-selection 和 horizon 决定不属于 S0 实施。

## 质量与降级路线

数据质量独立于模型误差：INVALID_EXCLUDE / SUSPECT_REVIEW / VALID_EXTREME_KEEP。保留真实峰值；所有修正只产生带 provenance/hash 的 derived artifact，原始 authority 不变。

完整 archive 可用于高等级历史实验；部分覆盖仅用覆盖期并单列 proxy；访问受阻不等于 archive 不存在。缺失 actual 不是 zero，显式源零与授权 Base-day zero 也须区分。S0 不决定 cohort、winner 或 promotion threshold。

普通 CI 仅使用 synthetic fixtures，不需要网络或私有数据。生产层权限隔离、真实 vault 和预测先封存后解锁必须在后续授权阶段实现并独立验收。
