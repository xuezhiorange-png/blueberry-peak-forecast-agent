## 4. S1 — Hierarchical Forecast Reconciliation

正式层级仅 BASE → REGION → COMPANY，FORECAST_ATOMIC_ENTITY_TYPE=BASE。
FARM_HIERARCHY_ADMITTED=false：历史 farm/member identity 是 canonical base_id
映射输入，现有 authority 不能证明独立正式父节点。
FACTORY_HIERARCHY_ADMITTED=false：Base→Factory 是 routing/allocation，
不是稳定产量 ownership hierarchy。

RECONCILIATION_METHOD=BOTTOM_UP_EXACT_SUM。
不得使用 MinT、top-down、middle-out、parent model fitting 或统计 reconciliation 搜索。
每日必须满足 sum(Base)=Region、sum(Region)=Company，
并验证 sum(all Base)=Company 的直接路径一致。

MISSING_CHILD_AS_ZERO=false。
应有 N 个 Base 但仅 N−1 个合法预测时：
status=INCOMPLETE_CHILD_COVERAGE，official_aggregate_kg=null。
可提供 diagnostic subtotal，但不得冒充正式 Region/Company forecast。

Region/Company single-day peak 与 rolling-7 peak 必须从聚合 daily curve 重算；
不能 sum(child peaks)，并列 EARLIEST_DATE。
输出至少包括 hierarchy snapshot/hash、reconciliation run、daily aggregate、
适用的 season/H7/H15 totals、single-day peak、rolling-7 peak、child coverage、
source forecast IDs/hashes、result hash。
要求 deterministic、immutable、append-only，不修改 source forecast。

## 8. S5 — Business Loss Contract

R1 冻结最简单确定性的非对称损失：

`BusinessLoss = C_under × max(actual − forecast, 0) + C_over × max(forecast − actual, 0)`

C_under / C_over 必须由 Owner/business supplied，或明确 synthetic scenario。
不能虚构公司真实成本。
输出 underforecast_kg、overforecast_kg、underforecast_loss、overforecast_loss、
total_business_loss；不同 forecast/planning bound 只能在同一 cost contract 下比较。
CANONICAL_COMPANY_COST_ESTABLISHED=false；REAL_ROI_VALIDATED=false。
没有真实成本 authority 就不能声称真实 ROI、节省金额或财务收益。

labor / cold-storage / packaging / transport / quality loss /
emergency capacity cost 为未来扩展，本阶段不实现。
依赖冻结 forecast/interval contract，不生成另一套模型。

## 9. S6 — What-if Decision Simulator

WHAT_IF_IS_SCENARIO_SIMULATION=true；WHAT_IF_IS_NEW_FORECAST_MODEL=false。
输入包括 saved forecast、uncertainty planning level、daily handling capacity、
optional buffer capacity、C_under、C_over。
若使用人员换算，workforce_count 和 productivity_kg_per_person_day 必须显式 supplied：

`daily_capacity_kg = workforce_count × productivity_kg_per_person_day`

禁止隐藏默认生产率。
输出 overload dates、daily overload kg、cumulative shortfall、max backlog、
capacity utilization、under/over quantity、business loss、scenario comparison/ranking。
Scenario A/B/C 必须使用同一冻结 forecast / hierarchy / loss contract。
只提供 decision-support scenario result，不自动执行经营动作。

排除 multi-factory routing、vehicle routing、cold-storage optimization、
automatic peak shaving、LP/MILP、reinforcement learning、automatic execution、
workforce scheduling system。
