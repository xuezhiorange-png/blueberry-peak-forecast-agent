## Scientific question and source authority

This experiment observes historical coverage and width of a research-only
uncertainty envelope around **unchanged, already sealed** V0.15 S5 final-fit M1
predictions. It does not train, refit, tune, or re-execute the point model.
The model is `V0_15_S5_M1_RIDGE`, a retrospective research point forecast,
not a production-approved model. Both 2025–2026 and its labels were previously
exposed. This is EXPOSED_OOT, not blind, pristine, prospective or strict PIT.
2026–2027 actuals remain prohibited and are not a dependency.

The binding is exactly 8,775 origins and 131,625 D1–D15 target rows. Predictions,
model/config identity, prediction seal, target rowset, full label file and the
filtered common labelset are pinned to the public frozen S5/S2 evidence.
The operator does not rematerialize S2 data or rerun S5. A missing/drifted source
fails closed; there is no retraining, source substitution or rowset fallback.
Actual zero, point zero and extreme errors are retained.

No TRAIN or VALIDATION residuals enter calibration. Validation predictions were
made by a different fit state, whereas all selected OOT predictions share the
same final TRAIN+VALIDATION M1 fit. Combining those residuals would change the
scientific contract. This R1 deliberately uses only final-fit EXPOSED_OOT.

## Frozen algorithm

Policy: `V0_16_ROLLING_DATE_BOUND_CONFORMAL_R1`.
Calibration grain: BASE target row. Pooling is global across Bases, but strictly
within the same lead day. There are fifteen separate pools and no cross-lead,
Base-specific, Region, area, season-position or magnitude buckets.
Each eligible row contributes one score: no weighting, normalization, decay,
outlier removal, winsorization, clipping or heuristic minimum sample size.

For evaluation origin O, a calibration row C must have the same frozen point
model and lead, C.origin < O, and C.target_date < O's Asia/Shanghai local date.
Origins must be timezone-aware and exactly 17:00 Asia/Shanghai. Target dates
must equal local origin date + lead (1–15). The origin day's actual is excluded,
as are same-origin residuals, even those for another Base. Scores are inserted
only when their target business date has strictly passed.

Two predeclared score families are used without result-dependent selection:

- Two-sided PI: `abs(actual_kg - point_kg)`.
- Upper planning: `max(actual_kg - point_kg, 0)`.

For nominal c in {4/5, 9/10}, sort the n scores and take the 1-based order
statistic `k = ceil((n+1)c)`. Integer arithmetic implements the ceiling; there
is no interpolated percentile. If k > n, output null bounds and
`NOT_COMPUTABLE_INSUFFICIENT_CALIBRATION`. The mathematical minima are n=4
for 80% and n=9 for 90%; no n=30/50/100 gate is invented.

PI lower = max(0, point − absolute-score q); PI upper = point + absolute-score q.
Upper planning bound = point + underprediction-score q. There is no upper cap.
PI90 must contain PI80, and upper90 ≥ upper80 ≥ point whenever computable.
Coverage includes both endpoints; upper coverage means actual ≤ upper bound.
Non-computable rows are counted explicitly and excluded only from coverage's
computable denominator, never from the candidate rowset.

Core calculations use Decimal/integer/date types only. Decimal summaries use a
local precision of 50; no numpy/pandas quantile or native-float calculation is
used. Deterministic ordering is origin, Base, lead, row key. Sorted mature-score
state avoids repeatedly scanning all history for each evaluation row.

## Semantics and limitations

Point forecast is **not proven P50**. A two-sided 80/90 prediction interval is
not a P80/P90 quantile, and a one-sided upper planning bound is not established
as a true conditional quantile. Legacy V0.3 quantile contracts, enums and
schemas remain untouched. Empirical coverage cannot confer quantile semantics.

This is `RETROSPECTIVE_DATE_BOUND`, not exact historical available-at proof.
Recorded dates enforce temporal direction, but historical ingestion/publication
at the precise cutoff has not been proven. Exchangeability/stationarity and
future nominal coverage are not claimed. Repeated/overlapping target windows,
cross-Base scale differences, season drift and pooled heteroskedastic residuals
remain limitations of the predeclared method, not grounds for hidden retuning.

H7/H15 coverage means **daily target-row** coverage over leads 1–7 / 1–15.
It is not a cumulative-total prediction interval. Region/Company calibration is
not implemented. Summing Base interval endpoints does not establish aggregate
80/90 coverage, and S1 point reconciliation/schema/persistence is unchanged.

Engineering PASS means faithful contract execution, temporal safety, exact
source binding, replay, privacy and honest reporting. It does not require
empirical coverage to meet nominal. Undercoverage or wide intervals are reported
as observed; they do not trigger a new pool, score, level or method in R1.
There is no SUPPORTED model-promotion classification. Production approval and
prospective interval coverage validation remain false. Prospective validation
requires independent future authority.

## Custody and operator

Use `scripts/run_v0_16_s2_uncertainty_calibration.py`, not the production CLI.
Path arguments `--s5-output-root`, `--dataset-root`, `--output`,
`--replay-output`, `--public-output` are operator-local and must not be published.
Run each phase in a fresh process:

1. PREPARE verifies public authority, immutable private prediction bytes, model
   artifact/config hashes (without executing/loading coefficients), the original
   seal, common rowset and dataset manifest metadata. It writes contract and
   source-binding-prelabel with LABEL_BYTES_READ=false. It does not open label
   bytes. Policy identity also binds implementation and frozen evidence hashes.
2. RUN checks the complete PREPARE contract and source hashes, writes a durable
   started marker, and only then opens the single frozen OOT label artifact.
   It verifies the full-file hash, complete envelope season/split, logical-key
   uniqueness, label row/vector hashes, D1–D15 calendar, common-key pairing and
   filtered label digest before calibration. A current-season envelope fails,
   rather than being filtered away. Any failed attempt is retained, not hidden
   or overwritten; corrective scientific execution needs owner authority.
3. REPLAY verifies the primary contract and runs the same preparation/calibration
   into a new independent private output directory. Different process identities
   are recorded in separate custody receipts, excluded from deterministic bytes.
4. PUBLISH verifies both source-bound contracts, different processes, exact
   private interval/target/base-summary bytes and aggregate bytes/hashes. Only
   then does it emit sanitized public evidence. No private rows are copied.

All source artifacts are read-only. Consumed source hashes are checked again
after execution. No S5 consumed marker, seal, prediction, manifest or model is
changed. Derived private files are exclusive-create mode 0600, directories 0700,
outside the repository and source roots. There are no private paths in public
artifacts, stdout summaries or exception messages. Stable value-free failure
codes replace internal exception text.

Private outputs contain target rows, intervals/coverage flags, actuals, point
values, pool maturity traces and per-Base details. Public evidence contains only
aggregate counts, coverage/gaps, width/expansion, D1–D15 summaries, H7/H15 daily
coverage, aggregate Base breadth, hashes, policy and custody statements.
