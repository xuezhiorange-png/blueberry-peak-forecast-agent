### Q3. 怎样建立跨季生产周期时间特征？

业务上每个 Base×season 主要有一个“剪枝→促早→开花→采收”周期；它是**显式关联的主周期假设**，不是强制每季四个事件齐全、先后固定或所有子成员同日发生。

- 周期身份：`cycle_id` 绑定 Base、season、production_system、成员关系版本、周期声明来源。明细按 Base/Farm/Subfarm/Plot/Variety/Season/production_system 的完整身份隔离。三制度 `DECIDUOUS_NATURAL`、`DECIDUOUS_FORCING`、`EVERGREEN` 不混合；自然落叶和常绿没有促早记录不等于缺陷或零天促早。
- 周期起点由每季显式的起点/主剪枝事件引用确定。不同产季可以不同日期，也可以跨公历年；不默认 1 月 1 日、7 月 1 日、上一季日期或第一条剪枝。多次剪枝全部保留，只有显式 primary 引用可作为锚点；主事件含糊返回 NOT_COMPUTABLE，不择最早日期凑齐。
- 每个事实关联使用 V0.20 `record_id`、package/mapping/source/vocabulary Hash 及修订身份。缺少成员或地块权威保持 UNMAPPED；只能通过明示的 synthetic 关系演练，不能把相同空键合并。跨季地块变更需连续性声明，换苗不能按同名地块推定同一株群。
- 拟输出 `days_since_cycle_start`、`days_since_primary_pruning`、已观测促早/普通开花/明确物候阶段的经过日数，以及已完成阶段间隔。起点变化使用 `date` 相减，不以年内序号比较跨年。
- date 精度保留原文与区间。对于事件日区间 `[a,b]`，在 origin 本地业务日 D 的经过日范围为 `[D-b,D-a]`；仅当上下界相等且事件已合法可见时输出单值。两个事件的间隔为 `[B.lower-A.upper,B.upper-A.lower]`。缺失为 null 和原因；不把月/年精度提升成某日或 00:00。
- PLANNED、OBSERVED、UNKNOWN 分通道，计划可作为明确“当时已知计划”描述，但绝不输出 `days_since_observed_*`；未知促早方式保留，不能映射为加温/休眠解除。开花开始/盛花/结束不自动转成百分比阶段。
- 采收开始/结束只作为同样受时点约束的已观测事件或独立标签。未来真实采收结束、总量或峰日不能反向补齐 origin 的周期特征；无法使用的事实仍留在账本。

S1 只形成时间特征准备，不把它们变成新模型输入维度。S0 不实现这些计算。

### Q4. 怎样检查换苗、密植及品种面积变化？

S2 通过**显式跨季连续性映射**比较相同成员、品种、制度和面积口径的两个版本；保留来源键、有效期、单位、生产状态和来源 Hash。不同 Base、成员、品种或产季不会因同名相互冲突。

种植/投产/有效面积分别报告前值、后值和差量；只有同单位、同口径且非零前值才报告比例，否则不可计算。换苗记录保留原/新株群、发生区间、对象、来源及计划/观测属性；品种替换单列退出与进入，不当作同品种面积趋势。密植需要明确株数和测量面积、单位、有效期及方法，不能从总量或树龄反推。V0.20 尚无完整换苗/密度观测字段，S2 只允许**可选、版本化的研究侧补充声明**与原包关联，不修改农事注册表、地块主数据或导入器；材料不在则 NOT_PROVEN。

合成场景预先指定“无变化、面积增加/减少、品种替换、换苗、密度变化、混合制度、来源断裂/冲突”等输入事实。输出结构和可比性变化，**不输出产量倍率或固定峰日偏移**，也不调用预测器宣称某操作使产量增加。

### Q5. 怎样避免未来农事信息泄漏？

输入包只是事实账本，不能整体当作 origin 可用特征。S1/S3 将其分为账本、按 origin 的特征快照、独立标签三部分。

1. 显式登记业务时区、origin D、带时区 cutoff；沿用现有滚动规则：观测业务日 `<D`，目标为 `D+1…D+7/15`。同日完整观测不自动可用。
2. OBSERVED 事实的业务区间需已结束于 D 之前；可信 `observed_at`、`recorded_at`、`known_at` 及来源时钟、相关映射/面积/修订可见性均须有证据且不晚于 cutoff。先检查类型和顺序，再复用 PIT 可见性谓词；不因已填 known_at 就自证权威。晚到修订不污染已封存快照。
3. `observed_at` 是观测发生时刻，`recorded_at` 是来源记录时刻，`known_at` 是可见性证明指向的时刻，不互相代填。Production Plan 的 `available_at: date`、日级 known_at、当前浏览器处理时间或事后文件时间不能证明严格 PIT。证据不足仅 DATE_BOUND/PIT_NOT_PROVEN，不进入声称严格 as-of 的可计算集合。
4. 未来实际事件、未来实际天气、未来采收、季末总量及峰日均不能进入特征。合成测试改动 D 及之后事实、标签和晚到修订时，D 的合法特征/封存结果不变；改动合法 D−1 事实应产生可解释变化。
5. 全量账本读取范围如实记录，预测/评价接口分开。即使在 synthetic 中模拟可信时间，也始终 `STRICT_PIT_VALIDATED=false`，不升级为真实时点验证。

### Q6. 怎样区分完整产季、明确剩余产季与任意起点 7/15 日？

| 评价族 | 冻结支持和日期边界 | 输出与限制 |
| --- | --- | --- |
| FULL_SEASON_PEAK | 事前声明完整产季 `[season_start, season_end]`、单一 origin/签发快照的完整逐日曲线 | 单日峰；最大连续 7/15 日累计、起止日和窗口内每日 kg；不拼接多个 origin 或后验挑最好发行点 |
| DECLARED_REMAINING_SEASON_PEAK | 显式 `[remaining_start, season_end]`，`remaining_start >= origin本地日+1`；终点来自事前固定的产季日历 | 同样的单日、连续 7/15 日峰和逐日量，名称始终带“声明剩余产季”，不能称完整产季峰 |
| ORIGIN_H7_PREFIX | 同一 origin 的 D+1…D+7 | 日量、前七日累计、局部单日峰；rolling7 只有一个起点 |
| ORIGIN_H15_LOCAL | 同一 origin 的 D+1…D+15 | 日量、十五日累计、局部单日峰和九个 rolling7 候选；rolling15 只有一个起点，不是产季峰 |

剩余产季必须在看标签前冻结 scope_id、Base/成员、season、timezone、origin/cutoff、显式起止日和 season-calendar Hash。起点可声明为 D+1，或明确更晚的研究起点，后者须披露被排除的早期剩余日期；不得使用未来实际峰/末次采收日期选边界。cutoff 必须早于第一个目标日期开始时刻。终点必须是已声明的 `season_end`；更早截止的片段不冒称本合同的剩余产季。未知终点、start>end、起点早于D+1或范围越界均不可计算。即使剩余天数碰巧为15，也必须因独立日历/范围声明成立，不能把 H15 改名后放行。

四类范围均要求同一支持内预测与标签逐日对应、连续完整。任意缺日、重复日期、负值/非法量使对应完整范围指标不可计算，不补零、不悄悄缩短范围。有效天数不足7或15分别返回 `NO_COMPLETE_7DAY_WINDOW` / `NO_COMPLETE_15DAY_WINDOW`，仍保留其他可计算指标和失败成员。完整季节或声明剩余季节的最大连续窗口按累计kg选取，并列选最早起日；单日峰并列最早日，返回峰窗口内每日向量。预测与标签在相同支持内分别选自己的最大窗口，不用实际峰窗重新缩放/选取预测，也不相加子实体峰值代替聚合曲线峰值。

权威日量沿用 Decimal、六位kg规则，指标除法沿用 precision=50；保存分子分母及原始 ratio，不通过显示值计算。全零actual：峰量仍为0，峰日期/起点误差 `NO_POSITIVE_ACTUAL_PEAK`，不得造成假命中。预测全零但actual正量时，预测最早并列峰的日期仍计入误差，不能删除模型失败。

**V0.19 十指标原样保留**，包括每日量、单日峰及rolling7；不修改其评分器或分母。`SEASON_TOTAL_WAPE` 仍仅允许完整产季，不用于剩余产季或 H7/H15。S3 计划新增以下独立命名的 **V0.21 additive protocol**，本 S0 仅冻结公式，尚未实现算术或评分平台。

记 c 为预注册合法范围/窗口，`p(c,d),a(c,d)` 为同日期kg；`P=Σp,A=Σa`；`s15_p,s15_a` 为各自最大完整连续15日窗口起点，`q15_p,q15_a` 为对应累计kg。

| V0.21 附加项 | 公式/权重/单位 | 范围与不可计算 |
| --- | --- | --- |
| V0_21_ROLLING_15DAY_PEAK_START_MAE | `Σc abs(s15_p-s15_a) / N_common_positive_actual_complete_windows`；每窗口等权，calendar days | FULL/声明剩余分别报；缺完整15日或全零actual不可计算 |
| V0_21_ROLLING_15DAY_PEAK_QUANTITY_MAE | `Σc abs(q15_p-q15_a) / N_common_complete_windows`；kg/15day-window | FULL/声明剩余分别报；合法全零actual保留；分母0不可计算 |
| V0_21_ORIGIN_WINDOW_TOTAL_MAE | `Σc abs(P-A) / N_common_complete_origin_windows`；kg/window | H7/H15分别报；不与逐日MAE混淆；合法全零actual保留 |
| V0_21_ORIGIN_WINDOW_TOTAL_WAPE | `Σc abs(P-A) / Σc A`；micro pooled ratio | H7/H15分别报；共同集合actual总量0不可计算，不加epsilon；不同于 `Σ(c,d) abs(p-a)/Σ(c,d)a` 的DAILY_WAPE |

每个 origin 另存预测累计、实际累计、signed error 和 absolute error；每日量仍用原 DAILY_WAPE、DAILY_MAE，并保留逐日同日期的 `p,a,p-a,abs(p-a)`，不能以累计正负抵消掩盖日误差。单日/rolling7继续原S1，rolling15用附加协议；全支持逐日比较与各自峰窗逐日向量分别展示，不能将不同日期行直接相减。

逐指标、逐范围、逐split预注册C0，按完全相同的 Base/成员、产季、目标日期、物理量和来源/成熟条件建立双方共同Cm；模型/fit身份分别保存，其他公共范围一致。零actual可进入数量MAE但不进入峰时MAE，因此Cm按指标确定，不能偷偷共用不适合的分母。失败、缺预测、未成熟/缺失标签、身份/口径/日历不匹配全部保留在C0账本；`NOT_COMPUTABLE_COUNT=N_candidate-N_common_computable`，每成员每指标仅计一次，覆盖及主原因沿用S1优先规则，并为新增15日不足添加明确原因。不得因某模型失败或误差大缩小C0；Cm子集结果明确为条件性对照。

**结构性零不是技能**：H7的rolling7、H15的rolling15只有一个候选窗口，其起点误差为0不代表峰时能力；所有FULL/剩余范围若长度恰等于窗口长度也相同处理。输出 `timing_skill_interpretable=false` 和候选窗口数，结构值单列，不把含这类结构值的起点误差作为模型技能论据；原S1及附加指标原始值仍按所列Cm/分母完整报告，不删成员。若另列非结构性子集，只作显式覆盖的诊断，不替换主分母。量误差仍可评价。空范围/空Cm不报0误差。

### Q7. 真实数据到来后怎样公平研究？

这只定义未来入口，不授予本版真实研究权限：

- 分别获得真实读取、合法成员/面积/来源时点核验、模型实验/拟合及独立标签评分授权。冻结本版准备包不等于研究 C0 已批准。
- 预注册 comparison_family、模型与配置、训练/验证/评价季节、Base/品种/制度、来源、四种物理口径、日历、origin/cutoff 和指标。田间采收、商品果、原果入库记录不能仅凭字段名认定等价；S8/S9 的来源证明及匹配逻辑直接复用。
- 在查看评价误差前冻结 C0、排除/缺失原因与成员 Hash。同样本、同目标、同训练时间切分、同数值策略的匹配对照只改变是否包含合法周期/结构特征。现有 Ridge 不接受新维度时，未来需单独获批的模型适配/训练；V0.21 不偷加系数或拟合新模型。
- 时间顺序训练、跨季验证、滚动 origin、合格时的实体留出；不用随机相邻日期拆分。已暴露的 2025–2026 保持 EXPOSED_HISTORICAL_BENCHMARK，不重新称为 blind OOT。
- 先冻结预测，再由独立评价路径打开成熟标签；各指标使用相同 Cm，完整保留失败、分子、分母、Base/日期/lead 覆盖、seen/unseen 和改善/退化。不删除困难基地制造优势。
- 完整产季峰、声明剩余产季峰与滚动窗口分面，数量与峰时同等审视。数量改善但峰时退化写 MIXED；可以 NO_STABLE_GAIN/INCONCLUSIVE。重叠 origin 不当作独立样本，未来统计应按基地/产季聚类或区块处理，样本不足不宣称显著性或因果。
