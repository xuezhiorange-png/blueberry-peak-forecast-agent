# V0_20 S2 — 质量、时间与版本

| 检查 | 处理 |
| --- | --- |
| 来源身份缺失/未匹配 | 保留原键、UNKNOWN/UNMAPPED，不建权威地块、不模糊匹配 |
| 面积缺失/非法/单位 | 空值为 null；显式0保留；非法值原文保留；非亩单位不转换 |
| 面积有效期 | 仅明确业务日可完整核对；逆序、同口径区间重叠及投产/有效大于种植面积报告冲突 |
| 管理操作 | 注册类型校验、同事实重复修订、缺前版/循环/多有效修订报告；不删除困难记录 |
| 计划与实际 | 分组保存；计划行有实际观测时间或实际使用计划强度报冲突 |
| 未知促早 | 原事件保留，无方法不解释成加温或休眠解除 |
| 物候顺序 | 同产季/成员/制度/来源版本/方法/样本/计划状态内检查；普通三个开花阶段和明确百分位分开 |
| 物候精度 | 月/年/无时区原文保留；缺方法/样本/质量报告不全；不制造精确日 |
| 时间 | 日精度不能冒充可信时刻；known_at早于recorded/observed报冲突；缺历史可见性仍PIT_NOT_PROVEN |
| 多产季 | 独立成员与事实分组；不混为相同记录或效果证据 |

冲突记录、缺失记录及多次操作全部留在准备包。状态可并存：一条结构齐全的事实仍可能 UNMAPPED、SOURCE_AUTHORITY_NOT_PROVEN、PIT_NOT_PROVEN。没有任何状态自动授予训练或预测权限。

## 版本身份

固定键排序的 JSON 规范化算法 `canonicalV020` 绑定源文件原字节 Hash、解析后原始行、映射、上游词汇身份、规范化事实、质量结果和限制。SHA256 形成完整 `V0_20-<digest>` 版本目录。没有机器时间、随机数、文件路径或 locale 排序影响业务摘要。

`agronomic-preparation.json` 包含准备摘要与其他四文件 SHA256。三个 CSV 包含行级来源、映射/槽位、日期精度、计划状态和问题码。HTML 转义所有文本、无脚本/网络，并展示来源/模型/PIT尚未证明。CSV 防公式注入。ZIP 使用固定元数据；与五文件字节一一对应。

原输入和旧版本始终不覆盖；同输入相同映射复用同一结果。更改源字节、映射、语义/词汇会产生新身份。源文件名不参与业务身份。原始单元格按源行存一次，宽表事实通过source_row_id和列/槽位可追溯。

## 未来研究边界

导出不是正式数据登记；本版本不向生产库写入，不读取真实农事，模型使用/预测调整权限恒为false。未来需要Owner独立授权和权威成员、面积、生效时间、来源记录/可见时间及产量标签验证；现有S6/S7/S8/S9算法与冻结证据不变。
