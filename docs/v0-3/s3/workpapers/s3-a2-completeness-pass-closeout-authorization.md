## 3. What this authorization grants

A later completeness PASS closeout R1 may, under a separate user 「可以实施」
gate:

1. Reuse the already-landed reviewed-set closeout classification, AVAILABLE-closeout
   classification, bindable-repository classification, live-origin construction,
   obtain, already-landed `CompletenessVerifier`, and the existing `#476`
   run-sync family only. No new SQLAlchemy API family.
2. Classify whether completeness PASS closeout preconditions hold for the
   already-produced live-origin catalog, reusing frozen completeness verification
   authority and the `CURRENT_S3_DAILY_ROWSET_COMPLETENESS_VERIFIED` /
   `S3_A2_COMPLETENESS_PASS_AUTHORIZED` facts.
3. Fail-closed when weather or plans are unavailable, catalog is not produced,
   empty, fixture-only, TEST-intersecting, not bindable, AVAILABLE closeout
   preconditions are not met, no coordinator-reviewed identity set exists,
   live-origin grains are not a reviewed set, or session / origin / actuals
   unavailable. Leave the default session provider unset after the classification
   call.
4. Classify **without rewriting** frozen catalog production bytes, frozen
   binding bytes, frozen completeness verifier bytes, grain identity-set bytes,
   bindable-repository bytes, AVAILABLE-closeout bytes, or reviewed-set closeout
   bytes.
5. Keep TEST sealed. Cutoffs must not be derived from harvest dates.

A later R1 may not:

- invent weather, plans, maturity, residual, tonnes, or identity-set members
- derive members from SOURCE_002
- treat the three live-origin policy grains as a coordinator-reviewed identity set
- add a new SQLAlchemy API family
- unseal TEST
- flip `NO_VERSIONED_INCUMBENT_FORECAST_ARTIFACT_IN_REPOSITORY`
- flip `NO_REVIEWED_GRAIN_IDENTITY_SET_IN_REPOSITORY`
- treat an in-memory structural pass as live-bindable or as `AVAILABLE` closeout
- flip `EVALUATION_INSTANCE_REGISTRY_AVAILABLE`
- flip `NO_BINDABLE_CATALOG_IN_REPOSITORY`
- flip `CURRENT_S3_DAILY_ROWSET_COMPLETENESS_VERIFIED`
- flip `S3_A2_COMPLETENESS_PASS_AUTHORIZED`
- treat templates as live weather or plans
- mutate frozen blobs listed in §4

This grant itself performs none of the above. Live-origin grains are not a
coordinator-reviewed identity set. Reviewed-set closeout R1 is not completeness
PASS. Already-landed `CompletenessVerifier` is not dataset-level completeness
PASS. Weather and plans block the actual PASS and must not be invented.
