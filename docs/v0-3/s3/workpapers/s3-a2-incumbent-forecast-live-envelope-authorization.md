### 3.2 Live envelope semantics (future implementation only)

The future R1 must preserve parent contract §§3–6:

1. Envelope assignment is explicit via `declared_catalog_source_kind`; must not
   infer live vs fixture from row tuple shape or `model_id` scan.
2. `catalog_source_kind` must not be added to `IncumbentForecastArtifactEntry`.
3. `registry.py` enum and forbidden/alignment sets must remain unchanged.
4. Default fail-closed: `obtain()`=`()`; producer `produce()`=`None`; adapter
   `artifact=None`; catalog default `NO_VERSIONED_INCUMBENT_FORECAST_ARTIFACT`.
5. Live envelope is necessary but not sufficient for bindable catalog; no live
   `BINDABLE` success enumeration.
6. Must not wire obtain→produce→adapter `default_factory`.
7. Must not invent cutoff lists, SQL, table names, hashes, tonnes, farm/cell
   lists, or distinct entry counts.
8. Must not read SOURCE_002 at row level; must not repository-scan; must not
   treat `harvest_business_date` as `forecast_cutoff`.
9. Must not add Alembic; `UNIQUE_ALEMBIC_HEAD=a7c3e9f1b2d4`.
10. Forbid H7 fixture
    `8e74d6be6bcadc087b2dd7a72dfcb588e849305db598aac5c02a954660f30c18` as live
    evidence or content identity.
11. TEST partition exclusion: `2026-03-10..2026-04-16`; default months 1–4.

The only implementation-status flip permitted by a future implementation PR is:

That flip must be recorded in `docs/v0-3/development-plan.md` §4.4 live block, not
only in an R1 pointer snapshot.
