## 3. What this authorization grants

A later evaluation instance registry AVAILABLE closeout R1 may, under a separate
user 「可以实施」 gate:

1. Reuse the already-landed bindable-repository classification, live-origin
   construction, obtain, and the existing `#476` family only. No new SQLAlchemy
   API family.
2. Classify whether coordinator-reviewed AVAILABLE closeout preconditions hold
   for the already-produced live-origin catalog, reusing frozen
   `EvaluationInstanceCatalogBindingService` and the
   `evaluation_instance_registry_available` field already recorded on produce.
3. Fail-closed when catalog is not produced, binding is `NOT_BINDABLE`, no
   coordinator-reviewed closeout exists, empty, fixture-only, TEST-intersecting,
   or session / origin / actuals unavailable. Leave the default session provider
   unset after the classification call.
4. Classify **without rewriting** frozen catalog production bytes or frozen
   binding bytes.
5. Keep TEST sealed. Cutoffs must not be derived from harvest dates.

A later R1 may not:

- invent weather, plans, maturity, residual, or tonnes
- add a new SQLAlchemy API family
- unseal TEST
- flip `NO_VERSIONED_INCUMBENT_FORECAST_ARTIFACT_IN_REPOSITORY`
- flip `NO_REVIEWED_GRAIN_IDENTITY_SET_IN_REPOSITORY`
- treat an in-memory structural pass as live-bindable or as `AVAILABLE` closeout
- flip `EVALUATION_INSTANCE_REGISTRY_AVAILABLE` to true unless frozen binding
  already classifies the produced catalog live-bindable **and** a
  coordinator-reviewed AVAILABLE closeout exists
- flip `NO_BINDABLE_CATALOG_IN_REPOSITORY` to false unless frozen binding already
  classifies the produced catalog live-bindable
- flip completeness verified or authorize completeness PASS
- treat templates as live weather or plans
- mutate frozen blobs listed in §4

This grant itself performs none of the above. Frozen binding already requires
`AVAILABLE_CLOSEOUT_REQUIRED_FOR_LIVE_FLIP` and has no live-bindable
classification; this family does not invent one.
