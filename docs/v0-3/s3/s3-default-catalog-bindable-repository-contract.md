## 3. What a later grant and R1 may do

A later grant (user 「授权」) plus R1 (user 「可以实施」) may:

1. Reuse the already-landed default catalog live-origin construction, obtain, and
   the existing `#476` run-sync family only. No new SQLAlchemy API family.
2. Classify whether the already-produced live-origin catalog is a bindable catalog
   in the repository, reusing frozen `EvaluationInstanceCatalogBindingService` and
   the `no_bindable_catalog_in_repository` field already recorded on produce.
3. Fail-closed when catalog is not produced, empty, fixture-only,
   TEST-intersecting, or session / origin / actuals unavailable.
4. Leave the default session provider unset after the classification call.
5. Keep TEST sealed. Cutoffs must not be derived from harvest dates.
6. Classify **without rewriting** frozen `catalog_artifact.py` or `binding.py`.

A later R1 may not:

- invent weather, plans, maturity, residual, or tonnes
- add a new SQLAlchemy API family
- unseal TEST
- flip `NO_VERSIONED_INCUMBENT_FORECAST_ARTIFACT_IN_REPOSITORY`
- flip `NO_REVIEWED_GRAIN_IDENTITY_SET_IN_REPOSITORY`
- flip `EVALUATION_INSTANCE_REGISTRY_AVAILABLE`
- treat an in-memory structural pass as live-bindable or as `AVAILABLE` closeout
- flip `NO_BINDABLE_CATALOG_IN_REPOSITORY` to false unless frozen binding already
  classifies the produced catalog live-bindable
- flip completeness verified or authorize completeness PASS
- treat templates as live weather or plans
- mutate frozen blobs listed in §4
- rewrite alignment contract §6

Live-origin grains are not a coordinator-reviewed identity set. Construction R1 is
not presence closeout and is not bindable-repository closeout. Binding already
requires `AVAILABLE_CLOSEOUT_REQUIRED_FOR_LIVE_FLIP`; this family does not
