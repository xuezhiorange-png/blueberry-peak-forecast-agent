## 3. Responsibility classification

- `GOVERNED_VALUE_PRESENT`: a governed value is already present and may be
  carried into the final payload; it is not itself source-owner acceptance.
- `GOVERNED_VALUE_PRESENT_OWNER_CONFIRMATION_REQUIRED`: the value exists in
  governed evidence, but `农场数据负责人` must confirm that it binds the
  attested source object/use. This is a confirmation responsibility, not a
  request to invent a replacement value.
- `SOURCE_OWNER_VALUE_REQUIRED`: a concrete business/governance value is
  absent and must be explicitly supplied by the source owner. No value is
  invented here.
- `SOURCE_DATA_DERIVATION_REQUIRED_NOT_AUTHORIZED`: the value requires a
  separately authorized source-derived preparation step. The owner request does
  not ask the owner to calculate it and this task does not access Source 002.
- `LATER_AUTHORITY_VALUE_REQUIRED_BEFORE_FINAL_ATTESTATION`: another accepted
  lifecycle, revision, visibility, or forecast-input authority supplies the
  value, but the schema-required leaf remains mandatory before final attestation
  issuance.
- `ISSUANCE_PROCESS_DERIVED`: the controlled issuance process creates or records
  the attestation event metadata. The owner must perform/authorize the event but
  must not manually manufacture the literal metadata value.
- `NOT_SCHEMA_REQUIRED`: an optional property outside the 57 required-leaf
  total; it is not a required final-attestation precondition.

the final truthful canonical payload by the issuance process, and must not be
guessed or copied from another artifact. The owner action is to attest/authorize
the event, not to fabricate these four metadata values.
