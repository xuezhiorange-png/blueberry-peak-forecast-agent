# V0.12-E3 operations and portable recovery

E3 is custody/recovery engineering, not S2. Real issuance remains disabled.
The frozen candidate remains RESEARCH_CANDIDATE; its comparator remains
COMPARATOR_BASELINE via external governance. Neither artifact is rewritten.

## A. Prerequisites

Use the reviewed E3 repository checkout and its Python 3.12 dependencies
(`pyproject.toml`, CI constraints). Check E1/E2 contracts and the frozen public
evidence. Have explicit permission to handle the private frozen artifacts.
The CLI has no public-authority override. CI uses hand-specified synthetic fixtures;
private artifacts are not CI inputs. No raw historical source or actual is required.

Directory publication uses exclusive atomic rename: macOS renamex_np RENAME_EXCL
or Linux renameat2 RENAME_NOREPLACE. Unsupported platforms/filesystems fail closed.
For publication, use an existing writable parent on the same filesystem as staging.
Each output directory must be nonexistent, not an already existing empty directory.
Files/registry/report outputs are create-only. Never delete existing data to retry.

## B. Build a recovery bundle

Set shell variables to explicitly authorized paths. These variables are local,
not repository configuration. Keep `$BUNDLE` outside Git and access-controlled.

```sh
python -m backend.app.area_yield.prospective_validation_cli v0-12-research pack-recovery \
  --candidate "$CANDIDATE" --baseline "$BASELINE" \
  --receipt "$RECEIPT" --seal "$SEAL" --execution-contract "$CONTRACT" \
  --public-evidence docs/next-version/evidence/next-area-size-20261002-r1.json \
  --output "$BUNDLE"
```

Pack copies bytes, not parsed/reconstructed models. It carries exactly two artifacts,
three original non-row-level provenance JSONs, frozen public evidence and README.
No optional metrics/data files are discovered or opened. The manifest inventories
these seven files, including size, SHA256 and role. Manifest itself has a canonical
byte encoding and self-hash. JSON duplicate keys and nonportable source references
are rejected rather than silently removed from originals.

`bundle_content_hash = digest(sorted inventory)` excludes new created_at, root and
mtime. Its ID remains identical across directories and repeated pack times. A
separate manifest self-hash includes metadata/clock. The bundle ID is an integrity
identity, not an independent signature or trusted timestamp. Keep the accepted ID
in a separately controlled custody receipt; an attacker who replaces every hash
and authority cannot be defeated with self-hashes alone.

## C. Verify

```sh
python -m backend.app.area_yield.prospective_validation_cli v0-12-research verify-bundle \
  --bundle "$BUNDLE"
```

Verification checks exact inventory, roles, hashes/sizes, canonical manifest,
relative paths, no symlinks or unexpected files, pinned public authority, both
artifact self-identities, E2 semantic/parity rules and frozen provenance contract.
Any rejection means STOP. Do not edit a manifest/hash to make it pass.

## D. Transfer to another machine/storage

Use approved private storage and preserve the complete directory, including manifest.
Verify before transfer and again after transfer; compare bundle ID/content hash
against the independently retained receipt. Do not put it in public Git, tickets,
uncontrolled email or public attachment storage: original artifacts include private
parameters and training Base identities. E3 does not implement encryption or an
external backup service. Keep at least one independently retained controlled copy.

## E–I. Restore, register, smoke-predict and verify seal

This complete guarded drill only needs bundle + compatible repository + dependencies.
No original source-directory argument or old registry is used.

```sh
python -m scripts.replay_v0_12_e3 \
  --bundle "$BUNDLE" --restore-root "$NEW_RESTORE_ROOT" \
  --test-output "$NEW_TEST_OUTPUT" --audit-output "$NEW_AUDIT_FILE"
```

It verifies/copies into staging, verifies the staged copy and publishes atomically.
It rebuilds a registry from restored files, checks all registry paths point to the
restored artifacts and performs guarded fresh-process inference twice per artifact.
The public 736-mu example is compared exactly. Existing E1 CLI issues TEST_ONLY,
verifies the seal and rejects REAL_PROSPECTIVE. No actual import/scoring is performed.
Synthetic clocks explicitly mean TEST_NOT_PROSPECTIVE, not historical real issuance.

For individual steps, existing CLI commands are also available:

```sh
python -m backend.app.area_yield.prospective_validation_cli v0-12-research restore-bundle \
  --bundle "$BUNDLE" --output "$NEW_RESTORE_ROOT"
python -m backend.app.area_yield.prospective_validation_cli v0-12-research register-artifacts \
  --candidate "$NEW_RESTORE_ROOT/artifacts/candidate-artifact.json" \
  --baseline "$NEW_RESTORE_ROOT/artifacts/baseline-artifact.json" \
  --public-evidence "$NEW_RESTORE_ROOT/public/frozen-evidence.json" --output "$NEW_REGISTRY"
```

The public declaration registry remains unchanged/inactive. Runtime registries
contain local absolute paths by design and must be newly generated, never copied
to a different machine. Their contents are not portable bundle authority.

## J. Export a sanitized audit

The full drill creates an audit. To export again to a new file:

```sh
python -m backend.app.area_yield.prospective_validation_cli v0-12-research audit-export \
  --bundle "$BUNDLE" --restored "$NEW_RESTORE_ROOT" \
  --registry "$NEW_TEST_OUTPUT/runtime-verified-registry.json" \
  --drill-result "$NEW_TEST_OUTPUT/restore-drill-result.json" \
  --store "$NEW_TEST_OUTPUT/TEST_ONLY-records" --output "$NEW_AUDIT_FILE"
```

Export revalidates bundle, restored files, path-bound registry and TEST_ONLY seal;
it does not accept a caller's PASS string as evidence. The report contains model IDs,
hashes, aggregate training scope, governed roles and engineering results, but no
paths, artifact bytes/parameters, training Base list or row-level business facts.
With only the export, another person can check its self-hash and public identities,
not reproduce inference or independently prove execution. Authorized access to
bundle + compatible code allows full engineering replay. No original historical
training or scientific backtest is reproduced at either level.

## K–L. Prohibitions and S2 gate

Never fit, refit, retune, re-score historical actuals, repair corrupted artifacts by
reconstruction, rewrite artifact roles, copy stale runtime registries or relabel
TEST_ONLY as real. No model promotion or business threshold is established.
S2 still requires separately authorized new information or a legitimate future
request and later complete actuals. E3 does not authorize S2, real issuance,
production use, tag/release or deployment. V0.12 remains incomplete.

## M. Incident response

| Incident | Action |
| --- | --- |
| Original directory/machine lost | Use independently retained bundle and compatible code; restore to new root, never retrain. |
| One artifact hash mismatch | Quarantine suspect copy; stop; locate a retained exact-hash copy. Do not rebuild. |
| Bundle/manifest mismatch | Stop before restore; compare independent receipt and trusted retained copy. |
| Runtime registry lost | Re-register from verified restored artifacts; no old-path registry copy. |
| Repository upgraded | Validate compatibility in a new test directory first; retain frozen artifacts/code identities. |
| Copy/publication interrupted | No valid official payload is published before validation; staging is not authority. After a process crash, do not promote leftover staging. |
| Real request arrives | Stop at separate owner S2 authorization gate; REAL_PROSPECTIVE remains disabled here. |

Atomic visibility and pre-publication fsync are not guarantees against every storage
failure, privileged tampering or loss of every backup. This is non-destructive
recovery engineering, not a managed backup platform.
