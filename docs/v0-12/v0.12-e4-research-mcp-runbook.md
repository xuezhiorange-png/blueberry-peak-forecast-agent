# V0.12-E4 research-only MCP interface

E4 is a thin interface over the delivered E1/E2 engineering. It is not S2,
scientific validation, real forecast authorization or production approval.
Base: `2ede214634b91430120d2a833344977c9609f0d7`.

## Operator prerequisites

Follow the E3 operations/recovery runbook to pack/verify the controlled portable
bundle and restore into a new empty root. Never commit the bundle, artifacts,
runtime registry, parameters, Base list or operator paths. Recreate the runtime
registry using E2 controlled registration from restored artifacts, not an old
machine's registry. No retraining or historical actual read is needed.

```sh
python -m backend.app.area_yield.prospective_validation_cli v0-12-research register-artifacts \
  --candidate "$CANDIDATE" --baseline "$BASELINE" \
  --public-evidence docs/next-version/evidence/next-area-size-20261002-r1.json \
  --output "$NEW_RUNTIME_REGISTRY"
```

Registry must be self-integrity verified with exactly one RESEARCH_CANDIDATE and
one COMPARATOR_BASELINE. Both must be content verified, active for research and
RESEARCH_ONLY, never production approved. Non-synthetic entries are rechecked
against the pinned E2 public authority and complete E2 registration metadata.
Synthetic CI artifacts remain visibly synthetic and cannot claim original R1
identity by merely toggling that flag. No fallback to the E1 public declaration
registry exists. MCP never discovers, restores or registers an artifact.

## Process configuration

```sh
export V0_12_RESEARCH_MCP_ENABLED=true
export V0_12_RESEARCH_RUNTIME_REGISTRY_PATH="$NEW_RUNTIME_REGISTRY"
export V0_12_RESEARCH_TEST_STORE_PATH="$NEW_TEST_STORE"
```

These are operator-owned process settings (AppSettings), not tool arguments or
HTTP headers. Use a dedicated TEST_ONLY file store outside the registry/artifacts;
its parent must exist and be usable. Default enabled=false. Disabled discovery
lists the unchanged ten business tools; enabled discovery lists fourteen.
Direct calls to a disabled research tool return V0_12_RESEARCH_INTERFACE_DISABLED.
Restart the process after changing cached process configuration.

## Existing stdio server

```sh
python -m backend.app.mcp.area_forecast
```

Use the existing MCP initialize, tools/list and tools/call protocol. No second
server or CLI framework is introduced. The four additional tools are:

- `get_blueberry_v0_12_research_readiness`: empty object, read-only.
- `create_blueberry_v0_12_test_forecast`: explicit write; duplicate request IDs
  rejected, so idempotent_hint=false.
- `get_blueberry_v0_12_test_forecast`: forecast_id, verified sealed daily readback.
- `verify_blueberry_v0_12_test_forecast`: forecast_id, integrity read; no inference.

Create arguments example (synthetic engineering input, not real issuance):

```json
{
  "request_id": "E4_TEST_ONLY_REQUEST_1",
  "target_area_mu": "736.000000",
  "target_season": "2028-2029",
  "base_or_farm_context": "TEST_ONLY_UNSEEN_BASE"
}
```

Only these four fields are accepted. Decimal area must be a positive string at
the existing precision. Season and full July 1–April 15 business window are
validated by E1, not interpreted as a natural full season. Server generates
requested_at from the system clock, injects registered model/hash/config
identities, fixes TEST_ONLY mode/authorization and constructs exact temporary
TEST_ONLY source/authorization files. They are not independent business evidence.
E1 owns inference, completion-time cutoff, locking, atomic immutable publication
and duplicate policy. No client model, path, date-window or authority override.
Request IDs and Base contexts use bounded safe stable identifiers.

Create returns compact totals/peaks/hash identities, not daily rows. Readback
returns sanitized daily curves. Verify never reruns inference. All responses
retain test_only=true and production/prospective approval=false. Area outside
training support carries the existing extrapolation warning; interpolation is
not accuracy validation. Readiness describes delivered engineering and current
runtime content verification, not model reliability.

## Existing Streamable HTTP, local only

```sh
export BLUEBERRY_MCP_CONNECTOR_SHARED_SECRET="$LOCAL_CONNECTOR_SECRET"
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 18082
```

The same server is served on POST `/api/v1/blueberry/v1/mcp/sse` and POST
`/api/v1/blueberry/v1/mcp`. Both remain stateless JSON-response Streamable HTTP.
Use `X-Blueberry-Connector-Key` and `Accept: application/json`. Missing/wrong
configured keys return 401. Empty secret is only appropriate for isolated local
acceptance. There is no new route, GET SSE endpoint, authentication system,
public tunnel or deployment. Future Doubao configuration may use these existing
settings, but no Doubao registration is performed by E4.

## Fail-closed behavior and operations

Disabled interface, unusable registry/store, inactive or unverified artifacts,
artifact corruption, invalid input, duplicate request and sealed-record corruption
produce bounded machine codes. Arbitrary exception text, SQL, URLs, paths,
parameters, credentials and stack traces are never returned. Unknown fields,
including real/prospective mode and model overrides, return
INVALID_REQUEST_DOCUMENT. Existing E1 real-mode gate also remains closed.

Readback only accepts TEST_NOT_PROSPECTIVE records. Runtime is revalidated on
every operation, including readback/verify. The operator may need to restore
missing artifacts before reading a valid old record; no silent fallback or
alternate model is chosen. Records remain in file-mode authority, not a claimed
PostgreSQL production authority. Local operator configuration and hashes are
not external signatures, trusted timestamps, tenant isolation or administrator-
proof authentication. No OAuth/RBAC is added.

No actual import, actual snapshot, locked scoring, training, registration or
recovery tool is exposed in MCP. Those remain separately controlled operator
workflows. Existing ten business tools retain their original implementations;
`forecast_blueberry_by_area` is not switched to the V0.12 candidate.

## Acceptance and next gate

Run focused E4 tests plus existing MCP and E1/E2/E3 regressions. CI uses
hand-specified synthetic artifact fixtures, never private R1 files or actuals.
Tests launch the existing stdio process and existing FastAPI app on loopback TCP,
verify both HTTP paths and connector authentication, and compare sealed readback
and verification across transports. Error injection and concurrent duplicates
must fail closed. This engineering replay does not refresh historical scores.

S2 still requires separate owner authorization and genuinely new information or
an eligible future business request with frozen area/model/source/authorization.
Then new outcome evidence and locked scoring would be needed. E4 does not enable
such issuance. Stable gain, blind/prospective accuracy, business acceptance,
production use and V0.12 completion remain unestablished.
