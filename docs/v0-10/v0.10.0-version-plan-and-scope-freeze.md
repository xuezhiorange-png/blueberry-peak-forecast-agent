## 1. Version purpose

V0.9 closed and released the theory-first biological forecast foundation: a frozen mechanistic model with 16 modules and 30 governed equations. It was not calibrated against real production data, was not historically backtested, and is not production ready.

V0.10 has one purpose: calibrate selected, identifiable parameters of the frozen V0.9 model using eligible real historical production evidence, then evaluate the frozen result on historical data excluded from calibration.

PRIMARY_GOAL=CALIBRATE_AND_VALIDATE_THE_V0_9_MECHANISTIC_MODEL_AGAINST_EXISTING_REAL_HISTORICAL_PRODUCTION_DATA
MODEL_STRUCTURE_SOURCE=V0_9_FROZEN_THEORETICAL_MODEL
VALIDATION_MODE=HISTORICAL_REAL_DATA_RETROSPECTIVE_VALIDATION

Theory determines structure; historical data estimate only admitted parameters; separate historical evidence tests the frozen result. V0.10 is not unrestricted model search and does not require the mechanistic model to outperform V0.8 to count as a completed scientific experiment.

The V0.9 causal structure, state definitions, biological mechanisms, and Biological Engine → Mature Inventory → Harvest State → Historical Harvest boundary are frozen for calibration. Parameter fitting may not reverse causal directions, remove inconvenient biological processes, add unsupported correction factors, or introduce a black-box residual model.

Base identity is not a hidden yield multiplier. Prefer global biological parameters, then cultivar-family, production-system, and climate/region parameters where scientific authority and data support them. Base-specific parameters require explicit scientific justification and are not the default.

## 3. Parameter lifecycle and admission

Every parameter must be assigned one operational lifecycle before calibration:

| Lifecycle | Treatment |
|---|---|
| CALIBRATABLE_FROM_EXISTING_HISTORY | Eligible only after passing the admission gate and pre-registration. |
| CALIBRATABLE_ONLY_WITH_STRONG_PRIOR | Estimate only with an explicit literature prior and scientifically supported bounds or penalty. |
| FIXED_LITERATURE_PRIOR | Hold at the cited prior; do not fit. |
| FIXED_THEORETICAL_REFERENCE | Hold at the declared synthetic/reference value; not an empirical estimate. |
| UNIDENTIFIABLE_KEEP_UNBOUND | Keep unbound; do not ask an optimizer to invent a value. |
| FUTURE_OBSERVATION_REQUIRED | Exclude from current calibration and identify the required observation. |

Admission requires all of: S4 does not classify the parameter as UNIDENTIFIABLE_IN_V1; it has meaningful sensitivity over a declared scientific range; calibration observations contain relevant information; validation outcomes are not needed; and bounds have scientific authority. Admission, bounds, parameter count, optimizer, objective, and diagnostics must be registered before fitting.

S4 identifiability counts are overlapping diagnostic dimensions, not mutually exclusive buckets: structurally identifiable 0, conditionally identifiable 19, confounded 24, observation-dependent 37, literature-prior-only 22, and unidentifiable in V1 12. Do not fit all sensitive parameters jointly. Report free parameter count, calibration observation count, and effective information content. Excessive complexity fails closed or requires a smaller pre-registered parameter set.

## 5. Validation protocol seal and leakage protection

Before any 2024–2025 harvest outcome is read by the V0.10 calibration process, S0 must create and hash a HISTORICAL_VALIDATION_PROTOCOL_SEAL containing:

1. Frozen V0.9 model structure hash and software/model version.
2. Calibration/validation dataset identities, row manifests, source authority, and hashes.
3. Parameter lifecycle, admitted free parameters, bounds, priors, and fixed values.
4. Calibration objective, component definitions, weights, optimizer/search procedure, stopping rules, and deterministic seed.
5. Validation cohort and inclusion rules.
6. Metrics, denominators, zero-actual policy, comparison cohorts, and pre-authorized acceptance/promotion criteria.
7. Scenario reconstruction rules for unknown production system, management, and initial state.
8. V0.8 baseline definition and frozen comparison protocol.

After sealing, validation outcomes cannot cause parameter retuning, scenario selection, objective/threshold changes, row removal, or model-family changes. If the protocol or seal changes, the original validation is contaminated for that changed decision and cannot be presented as its independent evaluation.

This plan invents no numeric accuracy threshold. S0 must establish any business acceptance thresholds with appropriate authority before validation outcomes are accessed. Version completion is an evidence/process gate and does not require beating V0.8.

## 6. Calibration objective and evaluation

Freeze a multi-objective calibration protocol before validation. It must represent at least:

- season-total harvest quantity;
- daily harvest distribution;
- single-day peak quantity and date;
- rolling-7 peak quantity and start date;
- phenology/timing proxies where authoritative observations exist.

Objective form and weights are S0 protocol decisions, not values to choose after viewing 2024–2025. Historical harvest is an observed operational output, not direct observation of physiological maturity.

Report season total, daily curve, single-day peak quantity/timing, rolling-7 peak quantity/timing, bias, error distribution, per-Base results, and authorized strata by known production system/cultivar and low/medium/high yield. Pooled metrics may not conceal Base-level failures. Diagnose scale, phenology, fruit-set/crop-load, fruit-development rate, maturity distribution, harvest capacity, unknown management, and production-system mismatch.

## 7. Historical inputs, scenarios, environment, and harvest

Every input carries one provenance status: OBSERVED, AUTHORITATIVE, LITERATURE_PRIOR, RECONSTRUCTED, LATENT, or UNBOUND. Missing bloom dates, pruning execution, flower thinning, fruit set, or greenhouse temperature do not authorize reconstructing facts backward from the final harvest curve. Unknown management remains UNKNOWN_MANAGEMENT_STATE.

Finite scenario families may represent uncertainty (for example, deciduous-natural, deciduous-forcing, or evergreen reference cases), but validation outcomes may not be used to search and select scenarios. If production-system authority is absent, keep it UNBOUND or use a pre-registered sensitivity envelope.

Historical environment backfill is allowed only from lawful, source-aware, location-aware, time-aware, deterministic sources. Outdoor weather must not be labeled greenhouse microclimate; where only outdoor data exist, retain microclimate uncertainty.

The comparison path is:

V0.9 Biological Engine → daily_newly_mature_quantity → mature inventory and loss → deterministic harvest capacity → harvested quantity → historical daily harvest

Do not bypass Harvest State by equating daily maturity to daily harvest, except in a separately identified control experiment. That control is not the default calibration path.

## 9. Frozen five-task sequence

Each task requires separate authorization; completing this plan or a preceding task does not authorize the next.

### V0.10-S0 — HISTORICAL_VALIDATION_PROTOCOL_AND_PARAMETER_ADMISSION_FREEZE

Freeze season lifecycle, parameter admission/lifecycle, bounds/priors, complexity gate, calibration objective/weights, validation cohort/metrics, acceptance/promotion criteria, baseline comparison, leakage controls, and artifact seal. Do not fit parameters or read validation outcomes.

### V0.10-S1 — HISTORICAL_INPUT_RECONSTRUCTION_AND_AUTHORITY_BINDING

Bind authorized inputs needed to run the frozen theory: productive area, authoritative cultivar and plant density where available, environment, production-system binding, management known/unknown state, and initial-state assumptions. Label each OBSERVED, AUTHORITATIVE, LITERATURE_PRIOR, RECONSTRUCTED, LATENT, or UNBOUND with source/hash. Validation inputs may be prepared; validation harvest outcomes stay inaccessible to calibration and parameter selection.

### V0.10-S2 — CALIBRATION_ON_2023_2024

Use only the sealed calibration cohort and admitted parameters. Run bounded numerical or Bayesian calibration under frozen objective/priors. Report estimates/posteriors, calibration residuals, stability, effective information, and confounding. Freeze and hash FROZEN_CALIBRATED_PARAMETER_SET_R1 before opening validation outcomes.

### V0.10-S3 — INDEPENDENT_2024_2025_RETROSPECTIVE_VALIDATION

Run frozen V0.9 model, parameter artifact, and scenario rules on the sealed validation cohort. No retuning or row removal. Report pre-registered metrics, V0.8 comparison, per-Base residuals, and failure diagnosis. Disclose prior V0.8/R2B empirical Stage A use.

### V0.10-S4 — 2025_2026_CONSUMED_BENCHMARK_REPLAY_AND_MODEL_DECISION

Use 2025–2026 only for descriptive audit, replay, diagnosis, and reporting with frozen choices. Do not select or retune parameters, scenarios, thresholds, or policies. Freeze a research-candidate decision for possible later prospective testing; this is not production promotion.
