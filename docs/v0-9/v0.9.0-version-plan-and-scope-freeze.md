# V0.9.0 Version Plan and Scope Freeze

**Version name:** `BLUEBERRY_FORECAST_AGENT_V0_9_BIOLOGICAL_FORECAST_FOUNDATION`
**Plan status:** frozen; implementation not authorized
**Planning baseline:** `a3f36b7b5461a10276a5887ff3c6e591883ecb4f` (`origin/main` at plan creation)

## 1. Version purpose

V0.8 closed a retrospective area-driven yield-model research cycle. Its global pooled yield remains a reference baseline, not an approved production model. The historical shrinkage signal was observed in temporal validation, but did not generalize consistently to the consumed 2025–2026 benchmark. That benchmark may not be reused for model, parameter, hyperparameter, management-rule, support-rule, or hybrid-policy selection.

V0.9 addresses a different question: how to build an auditable blueberry forecast foundation from plant state, phenology, production system, environment, management interventions, crop load, fruit development, and harvest realization. It is not another search for a retrospective fit to the V0.8 benchmark.

## 2. Frozen version objective and paradigm

```text
PRIMARY_GOAL=ESTABLISH_A_SCIENTIFICALLY_GROUNDED_AND_AUDITABLE_BLUEBERRY_BIOLOGICAL_FORECAST_FOUNDATION
MODEL_PARADIGM=MECHANISTIC_SKELETON_PLUS_DATA_CALIBRATED_PARAMETERS
```

The intended foundation combines:

- plant physiology and causal structure to define model states and mechanisms;
- authoritative literature and production evidence to bound parameter sources;
- enterprise observations to estimate or calibrate parameters when identifiable;
- future, prospectively sealed predictions and later actuals to evaluate generalization.

V0.9 need not establish production accuracy. Its success target is an executable, deterministic prototype with biologically meaningful states, management events, environment inputs, parameter provenance, explicit input/output contracts, and a prospective issuance boundary. The causal links below are the frozen investigation and contract scope; they are not a claim that every mechanism or coefficient has already been universally established. V0.9-S0 must classify universal, cultivar-dependent, and production-system-dependent evidence and record uncertainty.

## 3. Frozen causal model boundary

The planned causal path is:

```text
post-harvest plant state
  → structural / vegetative state and stored reserves
  → pruning and post-harvest management
  → flower-bud induction and differentiation
  → production-system-specific winter physiology
      ├─ deciduous natural: chill → dormancy release → natural forcing
      ├─ deciduous forcing: chill → dormancy release → managed forcing
      └─ evergreen: leaf retention and ongoing activity; no forced chill model
  → bud development → bloom cohorts (10%, 50%, 90%)
  → flower removal/thinning → effective flower load
  → pollination / fertilization
  → fruit set and fruit-cohort formation
  → Stage I → Stage II → Stage III development, influenced by source–sink state
  → color break → ripe fruit / maturity cohorts
  → daily newly mature fruit
  → existing Harvest State Engine:
      newly mature + opening inventory - loss + picking capacity
      → harvested quantity + closing mature inventory
  → daily harvest → single-day peak / rolling-7 peak
```

The model must not collapse biological maturity, harvest, and arrival into one quantity. V0.9's biological engine ends at `daily_newly_mature_quantity`; the existing Harvest State Engine remains responsible for mature inventory, loss, picking capacity, harvested quantity, and closing inventory. Arrival is a separate downstream concept and is not substituted for harvest.

## 4. Production systems

At minimum, the contracts distinguish:

| System | Intended pathway | Boundary |
|---|---|---|
| `DECIDUOUS_NATURAL` | Natural leaf fall, chill accumulation, dormancy release, natural warming, bud break | Chill and forcing responses require evidence and cultivar/system applicability. |
| `DECIDUOUS_FORCING` | Leaf fall, chill accumulation and satisfaction, then greenhouse closure/heating or other forcing | Forcing is an accumulated physiological response plus management/environment inputs, not a Boolean flag. |
| `EVERGREEN` | Leaf retention and continued physiological activity, potentially with limited or no complete dormancy | Do not force a deciduous chill model onto this system; define and validate a separate legal state path. |

The version does not assume that all protected blueberry production shares one annual cycle. Cultivar, production system, and region applicability must be explicit in the evidence and parameter records.

## 5. State and input contracts to be frozen

### 5.1 `PlantState(t)`

The state contract contains five groups:

1. **Structural:** `plant_density`, `cane_age_structure`, `productive_shoot_density`, `fruiting_wood_amount`, `pruning_state`.
2. **Vegetative:** `leaf_area_proxy`, `canopy_retention_ratio`, `shoot_growth_state`, `vegetative_vigor`, `carbohydrate_reserve_proxy`.
3. **Reproductive:** `flower_bud_density`, `flower_number_proxy`, `effective_flower_number`, `fruit_set_ratio`, `fruit_number`, `crop_load`.
4. **Phenology:** deciduous paths include `DORMANT`, `CHILL_ACCUMULATING`, `CHILL_SATISFIED`, `FORCING`, `BUD_SWELL`, `BUD_BREAK`, `BLOOM_10`, `BLOOM_50`, `BLOOM_90`, `FRUIT_SET`, `GREEN_FRUIT`, `COLOR_BREAK`, and `RIPE`. Evergreen systems may use a distinct evidence-supported path.
5. **Fruit cohort:** `cohort_id`, `origin_bloom_date`, `flower_quantity_proxy`, `fruit_set_quantity`, `fruit_stage`, `thermal_age`, `expected_ripe_distribution`, and `ripe_quantity`.

Unmeasured values may be represented as `PROXY` or `LATENT`; absence of measurement is never permission to fabricate a precise observed value.

### 5.2 Environment inputs

Source priority is frozen as `GREENHOUSE_SENSOR > FARM_LOCAL_SENSOR > NEAREST_WEATHER_SOURCE`. Candidate inputs are hourly air temperature, minimum/maximum temperature, root-zone temperature, relative humidity, and radiation/light proxy; substrate moisture, EC, and irrigation are optional. Each value must carry an observability classification: `OBSERVED`, `PROXY`, `LATENT`, or `UNAVAILABLE`, together with source, units, timestamp/grain, quality, and provenance. V0.9 does not require every input to be immediately available.

### 5.3 `ManagementEvent`

Represent management as an event record, not a Boolean feature. The contract includes `event_id`, date/time, `type`, `intensity`, `target`, `scope`, `source`, and `authority`. The event vocabulary includes `PRUNING`, `SUMMER_PRUNING`, `WINTER_PRUNING`, `FLOWER_REMOVAL`, `FLOWER_THINNING`, `FRUIT_THINNING`, `DEFOLIATION`, `LEAF_RETENTION`, `GREENHOUSE_CLOSE`, `GREENHOUSE_OPEN`, `HEATING_START`, `HEATING_STOP`, `DORMANCY_BREAK_TREATMENT`, `POLLINATION_START`, `POLLINATION_END`, `SHADE_APPLICATION`, `IRRIGATION_STRESS`, and `NUTRITION_INTERVENTION`.

### 5.4 Intervention semantics

- **Pruning** changes reproductive sink and future vegetative source. Track date, type, intensity, fruiting-wood removal ratio, and flower-bud removal ratio. `LIGHT`, `MODERATE`, and `HEAVY` are acceptable initial business grades only when their quantitative mappings are labeled as parameters to calibrate. Pruning is not a simple yield multiplier.
- **Flower thinning/removal** is distinct from pruning: it reduces effective flower load while approximately retaining leaf source. The model must allow fruit number to fall while source per fruit, mean berry weight, fruit size, or quality probability may rise. Yield is structured as `FruitNumber × MeanBerryWeight × MarketableRate`, not as a direct proportional function of flower count.
- **Forcing** is decomposed into chilling, forcing accumulation, and greenhouse management. For deciduous systems, `C(t+1) = C(t) + ChillResponse(T)` accumulates until a cultivar-applicable `C_critical`; only then may the state enter forcing, with `F(t+1) = F(t) + ForcingResponse(T)` advancing bud development. These equations are structural contracts, not pre-authorized parameter values.
- **Source–sink** is in scope at `SOURCE_SINK_MODEL_LEVEL=SIMPLIFIED_PROXY`. `SourceCapacity` depends conceptually on leaf area/health, radiation, temperature, water, nutrition, and stored carbohydrate. `SinkDemand` depends on flower load, fruit number, development stage, and berry growth potential. Their ratio may affect fruit retention, berry weight/size, development rate, vegetative growth, and future flower-bud formation. A full carbon-balance model is not required.

## 6. Season-total and maturity structure

The target biological season-total structure is:

```text
PotentialSeasonYield = Area
  × PlantDensity
  × ProductiveShootsPerPlant
  × FlowerBudsPerShoot
  × EffectiveFlowersPerBud
  × FruitSetRate
  × MeanBerryWeight
  × MarketableRate
```

Implementation may be staged or simplified when observability/identifiability requires it, but omitted terms, proxies, and priors must be explicit. The V0.8 value `855.5593226284052977280068913535048993216 kg/mu` remains an empirical/Bayesian prior reference only; it is not a production approval or a fixed biological law.

The future daily maturity structure is based on bloom cohorts and thermal development, not on treating the historical daily shape as the formal biological model:

```text
Maturity(t) = Σ BloomCohort(i)
  × FruitSet(i)
  × DevelopmentKernel(ThermalAge(i,t), cultivar, source_sink_state)

ThermalAge(i,t) = accumulated thermal development
  from cohort i's bloom origin through date t
```

The function family, temperature response, cultivar scope, and parameter sources must be established or marked uncertain through S0–S4; this plan does not supply fitted coefficients.

## 7. Frozen work sequence: five main tasks

The sequence is gated. Do not skip S0/S1 and start modeling; do not automatically launch the next task when a preceding task is complete. S0–S4 are the five main tasks; a later version-closeout task may synthesize their accepted evidence but is not a sixth research task and is not auto-authorized here.

### V0.9-S0 — `GLOBAL_PROTECTED_BLUEBERRY_BIOLOGY_AND_MANAGEMENT_AUTHORITY_REVIEW`

Review authority on annual plant cycle, flower-bud formation, dormancy/chilling/forcing, evergreen systems, pruning, flower/fruit thinning, pollination, fruit set, source–sink, fruit development/ripening, protected cultivation, and greenhouse temperature effects. Cover evidence from China, the United States, Japan, Spain, Portugal, and Chile to distinguish universal mechanisms from cultivar- and system-dependent ones. Deliver a scientific authority matrix, causal graph, term glossary, evidence hierarchy, and uncertainty register. No production code.

### V0.9-S1 — `BIOLOGICAL_STATE_AND_MANAGEMENT_EVENT_CONTRACT`

Freeze `PlantState`, `PhenologyState`, `FruitCohort`, `EnvironmentInput`, `ManagementEvent`, and `ProductionSystem`, including units/grain, authority/provenance, state transitions, and causal direction. At minimum specify what pruning, flower thinning, forcing, fruit set, crop load/source, and bloom-cohort thermal age are permitted to change. Contract only.

### V0.9-S2 — `EXISTING_DATA_OBSERVABILITY_AND_GAP_AUDIT`

Inventory existing project and enterprise evidence without initiating a large IoT program. Classify each theoretical variable as `AVAILABLE`, `DERIVABLE`, `PROXY_AVAILABLE`, `BUSINESS_CONFIRMATION_REQUIRED`, `NEW_COLLECTION_REQUIRED`, or `UNOBSERVABLE`. Explain which states/events can be supported now, which require next-season collection, and which remain latent. Produce a minimum-cost collection table covering pruning date/type/intensity, greenhouse close/open, heating/forcing start, 10/50/90% bloom, flower thinning, fruit-set sample, 10% color break, first harvest, 50% cumulative harvest, indoor hourly temperature, area, cultivar, and tree age.

### V0.9-S3 — `BIOLOGICAL_HYBRID_MODEL_CONTRACT_AND_DETERMINISTIC_PROTOTYPE`

Only after S0–S2 are accepted, implement the smallest auditable `Phenology Engine + Crop Load Engine + Fruit Cohort Maturity Engine`, allowing a simplified source–sink proxy. Require determinism, units, versioned parameters, source-aware provenance, and explicit missing/proxy behavior. Start with synthetic, golden, and training-only tests. A full photosynthesis, carbohydrate, or root-hydraulic simulator is not required.

### V0.9-S4 — `BIOLOGICAL_MODEL_PARAMETER_IDENTIFIABILITY_AND_PROSPECTIVE_READINESS`

Determine which parameters are estimable from existing evidence, require literature priors, require business observations, or are currently unidentifiable. Calibration may use 2023–2024 and 2024–2025 under a documented training/calibration boundary. The consumed 2025–2026 benchmark may be used for audit, replay, and reporting only—not parameter or model selection. Deliver biological-model readiness, 2026–2027 prospective forecast input requirements, and a prospective issuance/sealing/scoring protocol. This task does not itself issue a forecast.
