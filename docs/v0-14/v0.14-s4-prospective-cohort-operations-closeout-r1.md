## Scope、天气与模型

每个 attempt 在 designated AreaRevision store 重新验证 payload、known/effective 和
当时已知的 supersession lineage。限定杨柳 exact Base、2026–2027 season，优先
ACTUAL_PRODUCTIVE_AREA > PLANTED_AREA > REFERENCE_AREA；PLANNED_AREA 禁止。
同 priority 多个 terminal revisions 冲突时 fail closed，不按预测或便利选择。
新的正式面积仅能影响 known_at 之后启动的 slots，必须明确 supersede 旧 revision。

当前 394.000000 mu 仍为 owner-confirmed provisional REFERENCE_AREA，不是当季新实测。
每次重新核验 known_at <= attempt <= forecast_created_at，origin 位于 effective period。
未来正式面积以新 revision supersede，过去请求、面积快照和预测绝不重算。

天气只选单次 attempt 中最新完整 00/12 eligible run，真实 acquisition receipt
记录 fetched/known；known_at 必须不晚于 capture 后的 forecast_created_at。
“known at attempt”指在该正式 attempt 内实际取得的天气，不伪造为 attempt 开始时已取得；
provider cycle 不晚于 attempt 开始。完整要求 360h、84 steps、256 fields，无填补。
run age 在 forecast_created_at 计算，最多 36h（含端点）。这是运营 freshness guard，
不是 accuracy 选出来的阈值；允许当前 00Z、前一 12Z/00Z 回退但禁止更陈旧 run。

整个 cohort 固定 S2 Base10 C0、Base10+Weather8 W1、alpha、feature policy、artifact hashes
以及 S3 metric hash。C0 不消费天气。所有 ISSUED pair 使用同面积、同 15 个 target keys。
改变 cadence、时间、freshness、面积规则、provider、feature、算法、系数或 metric，
必须新 cohort/version，不得原地修改。

## 私有 registry 与中断安全

registry schema 为 `V0_14_PROSPECTIVE_COHORT_REGISTRY_V1`，genesis 绑定已有 seed。
每条记录绑定 sequence、slot_id、slot_date、status、previous_record_hash、record_hash；
record_hash 是不含自身的 canonical hash。scheduled records 按日期连续追加。
每个 slot 唯一，同 body 复用，不同 body SLOT_CONFLICT。

CLI 使用 exclusive registry lock、持久化 single-attempt claim、append+fsync、不可变
逐序列 checkpoints 和当前 head manifest。audit 检查全部链、checkpoint/head、顺序、
种子、ISSUED package 成员/hash、seal、models、PIT、目标、freshness。
audit 还报告 missing_due_slots；177 个未来 slots 不预填假状态，截止后必须逐日记录。

完整 package 先在私有 attempt-packages 内写完并验证，再原子移至 slot-packages。
未完成 staging 不算 accepted forecast，保留诊断，不重试；cutoff 后登记 TECHNICAL_FAILURE。
若 accepted package 已完成但 registry append 前崩溃，audit 的
`--reconcile-sealed-package --slot-date D` 只验证并登记原 bytes，不抓天气、不预测、不改 seal。
任何链/checkpoint 写入中断造成不一致，立即停止并保留全部文件，由 operator 审计；
不得清空 registry 或覆盖历史以继续。锁和哈希不是物理 WORM，删除整套本地存储
并伪造全部 metadata 不是这里宣称可抵抗的外部时间权威。

V0.14 uses internal PIT timestamps, immutable artifacts and an append-only hash-chained registry.
Git anchors provide additional public hash evidence when present, but no external trusted
timestamp/WORM authority is established. 后续 issued slots 可输出 sanitized anchor，
但每次 operational issuance 不强制 Git commit，不把 commit 时间冒充发报物理时间。

## Operator runbook（本轮不启用定时器）

以下路径均由 operator 配置为私有目录，不能提交；命令示意使用占位符，不嵌入真实路径。

1. 初始 `verify --initialize --registry <registry> --seed-package <existing-seed-package>`。
   只读取既有预测/seal/package，初始化 genesis，不调用模型。相同 input 可幂等复用。
2. 每日先 `audit-registry`。如有过去 due slot 缺记录，按日期顺序用
   `record-missed-slot --slot-date D` 补记 MISSED（仅记录未执行事实，不补预测）。
3. D 17:00–17:15 执行一次 `issue-slot --slot-date D`，提供 designated scope store、
   frozen S2 bundle、location authority、raw cache、registry、seed-package。
   相同 slot 不能通过第二次命令重抓/重发。网络错误记录 TECHNICAL_FAILURE。
4. 18:00 后核 registry：未运行的 slot 记 MISSED；中断 claim 且无 accepted package
   记 TECHNICAL_FAILURE；已有完整 accepted package 仅 reconcile，保留原时间。
5. `audit-registry` 核链/head/package/seal 和 due coverage。私有包及所有 checkpoints
   做 operator-controlled 保留/备份；不编辑历史。不读任何当季 actual，连 hash/stat 都不做。

CLI modes 为 verify、issue-slot、record-missed-slot、audit-registry，无 actual、harvest、
source25/source26、训练或评分入口。S4 本轮只调用 verify/init；没有安装或启动 scheduler。
后续运行属于 DATA_ACCUMULATION_UNDER_FROZEN_PROTOCOL，不是继续模型开发。
